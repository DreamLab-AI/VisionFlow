### F-01 — The shipped deployment compose inverts the code's fail-closed RBAC: public reads, owner-less, every authenticated key an Editor
- Topics: VC-22.9, VC-33.6
- Evidence: The code fails closed — `public_reads_enabled() ends .unwrap_or(false)` (rbac_gate.rs:126-133) and main.rs:807,813 refuses to start owner-less unless `RBAC_ALLOW_OWNERLESS` is set. But docker-compose.unified.yml:111-112 sets `RBAC_PUBLIC_READS=1` and `RBAC_ALLOW_OWNERLESS=1` "with the :-1 default", so "an unassigned pubkey resolves to Editor (role_store.rs:359)" via `UserRole::default_authenticated()` (rbac.rs:68-70). VC-33.6 confirms the compose sets `RBAC_PUBLIC_READS=1` (cited at :106 after two block moves).
- Failure: Deploy with the provided compose: all `/api` reads (graph data, ontology, provenance reports, insights) are anonymous; anyone who installs a NIP-07 extension and logs in gets Editor and can mutate graph/settings state for every user. The Rust defaults and the shipped defaults are two opposite postures, and the operator who never reads the compose env block gets the open one.
- Confidence: high
- Severity: high
- Marked by authors: yes (VC-22.9 "CORRECTED ADR-2070" note; called ADR-2027's "deliberate demo default and stays")

4. **Who can obtain a session Bearer token on `/wss/agent-events`.** The auth check is described (VC-27.13) but not the token-minting path or agentbox's outbound auth, so F-02's exposure (any logged-in user vs. a narrow service set) can't be sized.
5. **Any existing Oxigraph snapshot outside the scripts.** ADR-2103 is proposed and backup-sqlite.sh omits Oxigraph, but volume-level or ad-hoc snapshots taken operationally would not appear in this material; F-05's severity assumes none exist.

### R-1 — Erasure is a Pod-only delete: the RuVector embedding row survives and stays searchable
- Topics: VC-22.6, VC-26.6, VC-22.1, VC-22.10, VC-22.4
- Chain of events:

  4. The embedding row therefore "persists and stays searchable" in ruvector-postgres (docs/DATA-authority-erasure.md:87).

- Evidence: VC-22.6 DIVERGENCE and DRIFT notes as quoted above; VC-26.6 repeats "deleteAgentMemory has no RuVector counterpart"; VC-22.1 places vector/agent memory in RuVector (ruvector-postgres:5432) as a distinct write-master row of the authority matrix; VC-22.4 shows the sibling problem — GRAPH_PROVENANCE is append-only with "no DELETE, DROP or CLEAR" and retraction "only ADDS dl:validTo and deletes nothing" (provenance_writer.rs:218,478-502), with crypto-shredding only PROPOSED (ADR-2102).
- Warning signs visible today: the governing doc itself carries the tombstone-gap divergence (DATA-authority-erasure.md:87); ADR-2102/ADR-2103 still PROPOSED with zero implementation; the second RuVector read client added without a delete counterpart (Cargo.toml:133-138).
