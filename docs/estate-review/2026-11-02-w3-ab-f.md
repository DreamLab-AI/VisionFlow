# agentbox events, memory, learning and skills topics

I assessed four agentbox diagram topics: 17 (agent events and the BC20 bridge), 20 (RuVector memory path), 21 (learning loop) and 22 (skills and routing). That is 43 panels in all, each read line by line against agentbox `c57d9c0508f4`, with VisionClaw `86cdd7635582` read for cross-repository claims. All four topics were stamped at `6500582`, 120 commits behind the pin, so each was restamped and every citation re-derived. Dispositions: **3 accurate, 37 corrected, 3 accurate-with-limits, 0 inaccurate-unfixed**.

The most important finding: the trajectory recorder no longer writes to Postgres. It POSTs to `/v1/agent-events/trajectory` (ADR-2164), and enablement is now hook registration rather than env gates. The old AB-21.1 and AB-21.2 drew a mechanism that no longer exists. Two smaller defects are new:
- A task-token emit is attributed to the container identity.
- A rejected batch can already have been partly emitted.

Separately, the kg mapping an elevation beam advertises is persisted only when the candidate is published.

## Findings

### Topic 17

1. **The emit route gained a task-scope step the panel did not show, and task tokens fall to the container identity.** Trigger: a request authenticated by a per-task action token. `verifyAgentEventRequest` returns `ok` with `did` null (`management-api/lib/agent-event-auth.js:143-145`). `reconcileTaskScope` then forbids the request from asserting `source_urn` or `pubkey` (`management-api/lib/agent-event-auth.js:232-234`), and the route stamps an identity only when `auth.did` is set (`management-api/routes/agent-events.js:427-430`). Consequence: the publisher's ADR-2042 fallback writes `AGENTBOX_URN`/`AGENTBOX_DID` onto every task-token action (`management-api/utils/agent-event-publisher.js:146-151`), so the wire says the container acted and the task appears only in `metadata.taskId`. Closing it needs a task-derived `source_urn` (for example a `urn:agentbox:activity` minted from the task id), or the fallback suppressed for task-token requests. Recorded as **Tension** in AB-17.2.
2. **A batch can be partly emitted and still answered 403.** Trigger: a `/v1/agent-events/batch` call where item *k* claims a `source_urn` that differs from the verified DID. Items before *k* have already gone through `emitAgentAction` inside the same loop (`management-api/routes/agent-events.js:506-519`, `management-api/routes/agent-events.js:547`) when the 403 is returned, and the reply carries no ids for them. The task-scope check was moved ahead of the loop (`management-api/routes/agent-events.js:498-504`); doing the same with `reconcileSourceUrn` would close it. Recorded as **Debt** in AB-17.2.
3. **The VisionClaw envelope mirror is partial.** The publisher says VisionClaw mirrors its envelope (`management-api/utils/agent-event-publisher.js:296-298`). At VisionClaw `86cdd7635582`, `src/agent_events/schema.rs` `AgentActionEnvelope` has no `failure_mode` and no `authority_class` field, both of which agentbox puts on the wire (`management-api/utils/agent-event-publisher.js:326`, `management-api/utils/agent-event-publisher.js:335`), so they are dropped on ingest. Recorded as **Drift** in AB-17.1. Closing it needs the two fields added to the Rust struct, plus a parity fixture over the full envelope.
4. **The elevation path does not persist its own kg crossing.** `buildProposalDescriptor` calls plain `bc20.toVisionclaw`, not `crossOutbound` (`management-api/lib/kg-proposal-extractor.js:253`). The mapping is written only in `elevationPublisher.publish` (`management-api/lib/elevation-publisher.js:163-173`), which runs only for unblocked candidates once the signing stack loads (`management-api/routes/kg-elevation.js:229-233`, `management-api/lib/elevation-publisher.js:153-155`). Every candidate's LINK beam still carries `proposal_foreign_urn` (`management-api/routes/kg-elevation.js:204-217`). Consequence: a blocked candidate, or any candidate while federation is down, publishes a `urn:visionclaw:kg` address that `toAgentbox` cannot recover (`management-api/lib/bc20-provenance-bridge.js:287-289`). The old panel said the extractor persisted the mapping via `crossOutbound`, which was wrong. Recorded as **Debt** in AB-17.10. It closes if the extractor uses `crossOutbound(…, durableStore())`.
5. **AB-17.10 mis-described the beam.** The panel said the observability emit was `CREATE` with `source_urn` = thing URN and `target_urn` = kg URN. The route emits `LINK`, with source/target ids hashed from the URNs, `target_urn` = the concept URN, and `source_urn` = the verified DID only when present (`management-api/routes/kg-elevation.js:204-217`, `management-api/lib/kg-proposal-extractor.js:284-288`). Corrected.
6. **The PROTOCOL-registry "URN crossing" row is stale, and so was the topic's divergence built on it.** The row says the Rust map is narrower, has no `bead` arm, and that ADR-2061 is only planned (`docs/PROTOCOL-registry.md:8`). At the pins the artefact is versioned 1.1.0 (`schema/federation-kinds.json:3`), and VisionClaw `src/uri/mod.rs` embeds it with `include_str!` and has a structural `bead` arm in `cross_from_agentbox`. Both sides cross agent, activity, thing and bead. AB-17.5 is corrected to say so, and a **Drift** marker is added against the registry row. The registry row needs updating; that is an agentbox doc change, outside this audit's write scope.
7. **Smaller corrections in topic 17:**
   - `AgentActionType` sits at line 17 and is a plain object, not frozen. The old citation `:13` landed on a comment.
   - `uris.parse` is at `uris.js:296`, not `:266`. The old line was a doc-comment `*`; the JEV advisory was right.
   - The kinds artefact has 21 rows with 16 `not-federated`, not 20 and 15. The `chain` row (ADR-2098) and the ADR-2105 `event_kinds` band are now drawn.
   - `JsonlUrnMappingStore` exposes `getByAgentbox`/`getByVisionclaw`, not `get`.
   - The env fallback now fills `source_urn` and `pubkey` together, and only when both are absent (ADR-2042).
   - Events are archived durably before ring eviction.
   - The memory-flash base URL falls back to `VISIONCLAW_API_URL`.
   - `toAgentbox` checks the store before any structural path, recovers `concept` from the store, and returns `urn:agentbox:agent:<pk>:_` without one.

### Topics 20, 21 and 22

8. **The trajectory recorder's persistence path changed (ADR-2164), and the topics had not caught up.** The hook holds no database client. It POSTs its rows to `/v1/agent-events/trajectory` (`config/hooks/trajectory-recorder.cjs:276-311`), and `management-api/lib/trajectory-store.js` writes them in one transaction (`:113-197`). The watermark advances only on a 2xx (`trajectory-recorder.cjs:529-543`). Enablement is the entrypoint registering or stripping the hook (`config/entrypoint-unified.sh:2039-2040,2075-2078`); the hook reads no gate variable. AB-21.1, AB-21.2, AB-21.3, AB-21.8 and AB-21.9 were redrawn.
9. **The aggregate's success threshold is 0.9, not 0.5, and promotion has three conditions.** The sweep counts a success only at `quality >= RUVECTOR_AGGREGATE_SUCCESS_QUALITY`, default 0.9 (`mcp/servers/lib/aggregate-effectiveness.js:197-200,224-227`). It also requires an attributable action and at least 3 distinct trajectories (`:244-256`), and drops evidence older than 90 days (`:207-210`). The module's own header still says `>= 0.5` (`:15`); that is a **Drift** marker in AB-21.4. The cursor gates a full recompute, not a delta (`scripts/ruvector-aggregate-sweep.mjs:334-349`).
10. **A misleading log line in the sweep.** When Xinference is unreachable, `run()` logs "aggregates will store without embeddings" (`aggregate-effectiveness.js:425-427`). The governed `memStore` it calls rejects unembedded writes unless `RUVECTOR_EMBED_REPAIR` is set (`mcp/servers/lib/memory-tools.js:277-294`), and nothing sets it, so every store fails. The behaviour is safe (ADR-2014 fail-closed); the log line is wrong. Recorded as **Drift** in AB-21.4.
11. **The distiller and the sweep compute different Wilson figures for the same action.** `ruvector-pattern-distill.mjs` says it reuses AGG_SQL's grouping (`:35-38`). Its `DISTILL_SQL` counts success at `>= 0.5`, with no deflation, no age window, no attributable filter and no trajectory floor (`:350-362`). Recorded as **Tension** in AB-21.5. Closing it needs the distiller to import AGG_SQL and `promotionVerdict`.
12. **Hybrid search gained RRF and ADR-2017 admission, which AB-20.5 did not show.** `RUVECTOR_HYBRID_FUSION=rrf` fuses rank lists and withholds the effectiveness bonus (`mcp/servers/lib/memory-hybrid.js:15-24,88-112,356-362`). The bonus is admitted only through `consumerAdmission`, checked before and after the corpus read (`:132-167`). AB-20.5 was rewritten.
13. **The Postgres credential source changed.** `ruvector-mcp.cjs`, the sweep, the distiller, the feeder and the recall harness all build their pool from `management-api/lib/pg-config.js`: connection parts plus a 0600 password file (`mcp/servers/ruvector-mcp.cjs:52-59`). `RUVECTOR_PG_CONNINFO` is no longer read by these processes; AB-20.1 is updated. Outside this audit's write scope: the workspace instructions still name `$RUVECTOR_PG_CONNINFO` as the connection string.
14. **The ADR-2090 per-project bypass has shipped.** AB-22.2's DEBT said the per-project gate was deferred. `projectBypassed` now stops escalation before the one egress site (`config/hooks/lib/skill-route.cjs:436-446,660`). The list is empty by default (`agentbox.toml:1321`), and it covers skill routing only, not factrail or jev-checkpoints (`docs/adr/ADR-2090-skill-routing-prompt-egress.md:121`).
15. **Further corrections in topics 20–22:**
    - AB-20.7 had read the `dry_run` return as a "none pending" branch (`memory-tools.js:379-384`).
    - AB-20.12 drew `expires_at` as a column; it is a `metadata` key (`memory-metadata.js:44`).
    - AB-20.12 drew `patterns.action`; the columns are `type`/`pattern` (`ruvector-pattern-distill.mjs:371-379`).
    - `ruvnet-kb` is protected only under `ENABLE_RUVNET_BRAIN` (`entrypoint-unified.sh:2621`).
    - D3's source of 107/120 is `ruvector-memory-state.md:8`. Agentbox `CLAUDE.md` no longer carries it, although `LEARNING-memory.md:258-262` still says it does.
    - AB-22.8 cited `main.rs:130` and `:169` for tier selection; those lines are a registry return and a relay backend. Tier selection is at `main.rs:133-134` and `:175-177`, and the binary defaults to `local`.
    - The recorder header's "zero duration is a bug → skip" contradicts the code (**Drift**, AB-21.1).
    - D4, the README listing the feed gates, is resolved.
