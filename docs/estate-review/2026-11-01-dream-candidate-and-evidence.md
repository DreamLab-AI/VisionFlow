# Dream-engine candidate confinement and evidence boundaries

Candidate formatting can write outside its worktree. A valid Rust attribute with whitespace bypasses the engine's literal substring check, and rustfmt modifies an external temporary file while reporting an applied formatting change. Separate probes establish lost receipt/history records, duplicate test identifiers concealing a failure, and admission checks weaker than their tracked-tree description.

This pass assesses both existing DE-01 panels, adds four DE-02 panels and reviews ADR-DE-003, ADR-DE-004 and ADR-DE-009 section by section. All nine local decisions and their index were read; the other six need further implementation assessment, especially source selection, night recovery and forge behaviour. Selected agentbox call paths establish how the library is consumed. This does not complete AB-23's 22 panels, the engine's own nested diagram corpus or the estate audit. Production source and decision statuses remain unchanged.

## Findings and acceptance work

Paths below refer to dream-engine at the source revision above unless prefixed with `agentbox`.

| Finding | Evidence and scope | Required acceptance |
|---|---|---|
| DE-A1 / high: formatter escapes its worktree | `crates/dream-core/src/candidate.rs:111-131` checks only the literal `#[path` substring before running local rustfmt. The probe adds `#[ path = "<temporary absolute path>"] mod outside;`. Rustfmt rewrites that external Rust file and returns `FormattingOutcome::Applied`. Worktree status at line 147 cannot see the external write. | Constrain formatter writes to the candidate filesystem, and parse or disable module traversal. Include whitespace, comments, conditional attributes, symlinked baseline modules and failed-format cases. A later rejection must not leave changes outside the candidate. |
| DE-A2 / medium: evaluated working files can differ from the recorded tree | `candidate.rs:546-558` evaluates after hashing/preparing the candidate, with no post-evaluation tree check. A local fixture evaluator rewrites tracked `value.txt`, prints success and leaves a dirty worktree; the gate accepts the supplied state/receipt. | Define which generated files may change, detect tracked-source mutation and bind results to the tested artefact. Run the final accepted patch against a fresh immutable input. Remote-runner correspondence remains a host obligation; this probe exercised LocalRunner only. |
| DE-A3 / high when per-test evidence is relied on: duplicate identities erase failures | `crates/dream-gate/src/pertest.rs:210-212` collects tests into maps and retains the last duplicate. Failure then pass accepts; reversing the order rejects. `crates/dream-core/src/testfmt.rs:80-89` also creates collisions: JUnit names `x, x, x~2` become `x, x~2, x~2`, hiding the middle failure. | Reject duplicate final identities, or define stable composite identities without suffix collisions. Test every parser and the pure gate independently. The probe supplies a passing top-level receipt: a genuine non-zero evaluator exit still vetoes acceptance, so this does not bypass that separate control. |
| DE-A4 / medium: persisted receipts collide | `crates/dream-gate/src/receipts.rs:288-307` names files with a lossy slug. Receipts named `a b` and `a-b` overwrite one another; reload returns only the latter. | Use reversible or digest-suffixed filenames and reject collisions before writing. Require a full capture/load/replay comparison for multiple evaluators. Missing required receipts should block replay; the observed loss is not itself evidence of false acceptance. |
| DE-A5 / medium: manifest archives overwrite earlier evidence | `crates/dream-gate/src/manifest.rs:297-317` archives by run ID, although model identity changes affect manifest content without changing that ID. Three revisions leave only the latest and the second revision. Two malformed manifests also overwrite the same `manifest-unparsable.json`. | Allocate non-overwriting archive names and propagate archive failures. Test repeated model/tool changes and repeated corruption. This is the freeze helper, not ADR-DE-007's separate hard-link reset archive. |
| DE-A6 / medium: admission does not establish tracked or meaningful evaluation | `readiness.rs:127-176,240-248` recognises simple command segments and checks filesystem existence. An untracked `scripts/check.sh` is admitted although absent from `git ls-tree HEAD`; `bash -c 'echo ok'` is also admitted. | Check nominated scripts against the dispatched revision. Treat command heuristics as diagnostics and validate evaluator sensitivity with controlled faults. These probes do not establish the state of every configured estate evaluator. |
| DE-A7 / API boundary: caller-supplied evidence remains trusted | `gate.rs:197-234` validates receipt identity but trusts its `outcome`; a supplied Passed outcome with exit 1 and failure text accepts. A synthetic applied state with no required evaluators and a non-tree identifier also accepts. Config-digest comparison is optional in `GateContext`. | Expose a checked assembly path or document/enforce caller preconditions. Do not label the pure gate an execution attestation. Readiness rejects empty required sets, normal receipt construction classifies raw output, and replay verification detects inconsistent receipt fields: the direct API probes deliberately omit those surrounding checks. |

DE-A1 contradicts the explicit confinement claim in ADR-DE-009. Its significance differs from the documented need to sandbox untrusted build scripts: formatting runs on the control plane before the evaluator runner. `SECURITY.md` describes the evaluation host's sandbox obligations, but that does not confine the separate local formatter process. The probe demonstrates a bounded file rewrite, not arbitrary code execution or a production compromise.

Agentbox `candidate_flow.rs:115-130` delegates to the affected candidate implementation. Its `engine.rs:1529-1560` supplies config-digest and parsed per-test evidence to replay, and `judge.rs:36-49` records through `replay::capture`, falling back to the same judgement if non-policy recording fails. `engine.rs:2015-2038` omits per-test evidence when parsing fails, leaving the top-level receipt in charge. These call paths qualify the direct API findings; a complete host/annexe experiment is still required. The adapter continues to call `Forge::publish_draft` directly at `engine.rs:1774`, so this pass does not establish automerge operation.

## Position and useful next demonstration

[SWE-bench's evaluation implementation](https://github.com/SWE-bench/SWE-bench/blob/main/docs/reference/harness.md) separates patch application, repository tests and reproducible Docker environments. [SWE-agent's introductory workflow](https://github.com/SWE-agent/SWE-agent/blob/main/docs/usage/hello_world.md) gives the model actions in a sandboxed execution environment. Dream-engine's reusable contribution is the smaller deterministic comparison, decision and evidence layer, with model access and scheduling owned by a host. These systems are adjacent reference points, not interchangeable products; no benchmark superiority follows from this review.

A useful user demonstration would give a maintainer one draft with the exact baseline, candidate, evaluator definitions, raw results and replayable judgement. Include a good patch, a semantic regression, a judge-changing patch, a formatter traversal attempt, duplicate test names, interrupted persistence and a nondiscriminating evaluator. Require correct refusal and preserved evidence before measuring acceptance rate, review time or cost. Those measurements would test practical utility more directly than nightly run counts or the existence of an ACCEPT label.

DE-01 now labels October activation as historical and preserves the known roster/release-manifest identity drift. DE-02 shows the current library boundaries. [Reproduction notes](evidence/2026-11-01/dream-reproduction.md), source comparisons, logs and retained artefact hashes accompany the assessment; whole-estate semantic review remains in progress.
