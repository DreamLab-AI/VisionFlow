## Findings and external-review adjudication

| Finding | Current source evidence | Decision and closeout criterion |
|---|---|---|
| **VC-A01 — ontology pull is not atomic across resources** | `src/services/ontology_pull.rs:304-342` verifies all downloads before mutations, but `:345-373` then creates containers, conditionally writes ACL, writes each content resource and finally writes the manifest. Every `put` can return independently; no rollback or generation switch exists. | ADR-2106's “every failure ... leaves the pod as it was” is false for storage-phase failures. Pre-fetch/hash failures leave content untouched; partial storage writes do not. Manifest-last enables retry but does not isolate concurrent readers. Inject failures at every PUT, verify visible generation, then choose staged atomic publication or reader generation verification. |
| **VC-A02 — ACL-preservation guarantee has an error branch** | `src/services/ontology_pull.rs:355` uses `exists(...).await.unwrap_or(false)` before writing the public-read ACL at `:359`. | An ACL probe error is treated as absence. If the subsequent write succeeds, an existing operator ACL can be overwritten. Distinguish not-found from storage error and prove the existing ACL survives a failed existence probe. This is a source-demonstrated branch, not an observed production incident. |
| **VC-A03 — PTX critique overstates what is broken** | `crates/visionclaw-gpu/src/ptx_policy.rs:233` uses a shared span parser, `build.rs:238` structurally validates output, and `ptx_loader.rs:336` delegates the runtime rewrite to it. | **VC-A04 — GPU absence has several explicit policies** | `src/actors/gpu/shortest_path_actor.rs:224-249` refuses SSSP without a context or after a kernel error. `:349-366` separately rejects dense APSP under NFR-7 because quadratic memory is forbidden. | VC-10.10 previously cited the removed **APSP** fallback as evidence for SSSP; corrected. Absence of universal CPU fallback is not itself a defect: require a per-operation degrade/refuse contract, observable error and a GPU-loss recovery test. Keep existing frame-drop/recovery gaps explicit. |
