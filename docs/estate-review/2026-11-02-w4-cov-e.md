# Audit wave 4: component coverage (w4-cov-e)

## Outcome

Every one of the 26 uncited components across these six repositories now has a disposition. The counts are 12 assessed, 7 covered elsewhere, 7 out of scope and 0 gaps. The evidence class is source tracing at the pinned revisions. Nothing was built, run or tested. Most of the uncited code is either already described by a dated report or is vendored, generated or harness material. What was left is mostly sound. `whelk-el` is the live EL reasoner, and at this pin it carries the `rule_bottom_left` fix that the whelk-rs fork lacks. The Obsidian views write to the DOM only as text, and both confirmation modals default to refusal. The assessed components produced nine low-severity findings. The most material are these: dream-machine's memory package labels a flat-file store as RuVector and can silently wipe its own store (COV-E-F1, F2); visionGraph's `weekly_ingest.py` is a divergent copy of the podcast pipeline that no longer runs (COV-E-F3); and both pipelines call confidence-filtered model output 'verified' (COV-E-F4). The main thing the corpus misses is that dream-machine's toolkit packages have no diagram topic of their own beyond estate/90.

## Findings

### COV-E-F1 (drift, low)

The module header says nights are stored as vectors in an RVF container for HNSW recall when RuVector is installed. In fact `openMemory` always builds `FlatMemory`, and with `backend: 'ruvector-rvf'` it overwrites the label to `ruvector-rvf` (:169).

- **Citation:** dream-machine:packages/memory/src/index.ts:4-6,159-170
- **Consequence:** A caller or telemetry that reads `backend` is told semantic recall is active while keyword scoring runs. Recall quality claims built on that label are false.

### COV-E-F2 (defect, low)

`load` turns any read or JSON parse failure into an empty list (:81-83). The next `remember` then persists that list over the file (:99-100 → :91).

- **Citation:** dream-machine:packages/memory/src/index.ts:75-84,86-92,94-101
- **Consequence:** A store that is corrupt or partly written, for example after an interrupted non-atomic `writeFile` (:91), is silently wiped on the next write, and all prior nights are lost. No package in the repository calls it yet, so there is no product exposure today.

### COV-E-F3 (drift, low)

`visionGraph/transcripts/weekly_ingest.py` presents itself as the weekly cron job, but the live jobs run agentbox's Rust port. The two have diverged: Python keeps confidence ≥ 0.7 flat (:486), while Rust uses tier thresholds of 0.7, 0.5 and 0.4 (verify.rs:13-20). An agentbox reference doc still names the Python file as an implementation of `write_assertion_ledger`, and XR-12 cites its `split_frontmatter` (:117) as a parallel parser.

- **Citation:** visionGraph:transcripts/weekly_ingest.py:1-21,486; agentbox:skills/podcast-knowledge-ingest/run-ingest.sh:3,11; agentbox:services/podcast-ingest/src/ingest/verify.rs:13-20; agentbox:skills/podcast-knowledge-ingest/references/pipeline-and-operations.md:19-20; VisionFlow:docs/estate-review/2026-11-01-parallel-implementations.md:439
- **Consequence:** A maintainer who edits or runs the Python copy changes nothing in production, or lands drafts under the older rules. Corpus references to it describe a path that does not run.

### COV-E-F4 (drift, low)

Both ingest paths name their output 'verified' (Python docstring: 'verifies them via Perplexity'). Phase 3 only filters by the model's self-reported confidence, and no external check runs in cron mode.

- **Citation:** visionGraph:transcripts/weekly_ingest.py:6,479-489; agentbox:services/podcast-ingest/src/ingest/verify.rs:1-5,22-40
- **Consequence:** Draft pages and ledger bullets carry LLM claims as 'verified' that nothing has checked. The drafts stay in `working/` and need governed promotion, so the effect is limited to mislabelled evidence. A grep of `docs/diagrams/agentbox` and `docs/diagrams/estate` for `phase_verify` finds nothing, and none of their `pass-through` hits concerns the podcast pipeline.

### COV-E-F5 (debt, low)

The legacy-toolchain migration guard is not run by CI, the release workflow or the nightly evaluator. It scans sibling checkouts on disk, and its `legacy-crate` condition (`project/crates/vault-core` present, :146-147) holds at the VisionClaw pin. The script was not run.

- **Citation:** ontomark:scripts/estate-guard.sh:2-3,32,146-147,169; ontomark:.github/workflows/ci.yml:35,62; project:crates/vault-core (present in ls-tree @86cdd7635582)
- **Consequence:** The DEPRECATION/EXP-10 migration has no enforcing gate. Residue can grow without any signal, and the guard can only be run by hand against working trees.

### COV-E-F6 (defect, low)

After a grant is sent, a failed ledger save is only logged (:194-196), and the save neither fsyncs nor checks the rename beyond `?` (:70-74). The in-memory ledger keeps enforcing limits until the process restarts.

- **Citation:** nostr-rust-forum:crates/nostr-bbs-sidestr-admin/src/cli/faucet_run.rs:70-74,193-196; nostr-rust-forum:crates/nostr-bbs-sidestr-admin/src/faucet.rs:75-76; nostr-rust-forum:crates/nostr-bbs-sidestr-admin/src/lib.rs:33
- **Consequence:** A restart after a failed save forgets those grants, so the faucet can pay the same script again within its window. That defeats the stated rationale ('forgetting grants would pay everyone again', faucet.rs:75-76). The impact is bounded because these chains' coins carry no value (lib.rs:33).

### COV-E-F7 (gap, low)

site-facts claims to be the one place pages take figures from. Its guard test checks only the specialist count and retired figures, not prices or accommodation. '£8M+' is typed by hand in three places, and the print flyer's prices are hand-copied with no check.
