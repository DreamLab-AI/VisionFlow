# Parallel implementations across the estate

At committed HEAD, eleven review clusters filed 145 parallel-implementation records. Merging records that describe the same defect leaves 134 distinct issues. By severity there are 2 S0-crypto, 23 S1-high, 73 S2-medium and 36 S3-low. Across the 145 records, 73 are CONFIRMED-LIVE (both paths reachable), 45 PARTIAL (one side half-wired or only conditionally reachable), 25 ONE-DEAD (a shipped path with no production caller) and 2 RESOLVED-SINCE-STAMP. Counted as distinct issues, that is 68, 40, 24 and 2. Another 18 hypotheses were rejected or folded into other records; they are listed below so nobody chases them again. Both S0 items are S0 *by category* (bespoke crypto format), not because a hot path is exposed. ABI-02 is a `nostr.key.enc` reader whose writer has been deleted, and ABR-11 is a hand-encoded X.509 fallback that fails closed.

The 23 S1 items fall into four groups:

- **Money and identity.** VisionClaw's `/pay` routes verify NIP-98 through a second verifier with no replay cache and no body binding (VCS-10 / XR-01). The default 31403 governance gate path accepts signatures structurally whenever `nostr-tools` throws (ABI-05). Forum NIP-05 names keep verifying after a member is deleted (FWP-04). Four NIP-98 verifiers disagree on URL matching and replay (ABI-09), and the XR client's post-connect carrier cannot pass the release `/wss` gate (VCX-01). Agent-event ingest accepts an unconfined `?token=` (VCS-11). codescape accepts a claimed presence DID unverified (VCX-03). Zone-grant copies already disagree on which grants are valid (FWP-07). The teller credit rule has three engines with different receipt keys (EST-08). Faucet and poker ledgers split across two stores by a flag (SET-06).
- **Ontology authority.** Two compilers publish ontology generations from the same visionGraph corpus (ONT-01 / ABM-07 / XR-02). Two parsers disagree on whether `public: "true"` is public (ONT-02, ONT-06). Two ontology stores are fed by different projections (ONT-14).
- **Key custody.** The identity port is half-wired, so eight processes still read keys directly (ABI-01). The role-secret precedence contract has drifted between three copies (ABI-04 / ABR-10). The server Nostr key loads through two paths, one of which ignores `*_KEY_FILE` (VCS-14).
- **Shared stores with two writers.** The memory adapter writes vectorless rows over governed ones (ABM-01). The API-keys GET reads a store nothing writes (VCS-15). agentbox config has five parser grammars (ABR-01). Gateway text bypasses the session plane (ABR-04 / ABI-12). Persisted URNs come from unchecked Rust minters (EST-05). Secrets backups have a plaintext twin (EST-13).

Three estate-wide patterns account for most of the volume:

- **The same contract is reimplemented in every repository with no shared fixture.** This covers NIP-98, NIP-01 event ids, gift-wrap unwrap, did:nostr documents, LDP helpers, teller credit, zone grants, adr-index-gen and the Nostr fixture corpus. Where a fixture does exist, it is often consumed on only one side, or a test skips it silently.
- **Migrations stop half way.** The "consolidated" target exists, is labelled canonical, and has no consumer while the legacy paths carry the traffic. Examples are `mcp_client_utils`, `project_model`, the identity port, the ADR-2084 cutover and `ontology-local.js`.
- **Retired paths keep shipping.** Some of them carry their own security logic that must be kept in step with the live path: fastwebsockets, the vault compiler, `dream-machine-nightly.mjs`, MAD relay supervision and `nostr.key.enc`.

## Method

The diagram corpus under `docs/diagrams` served as a map, not as truth. Opus cluster leads turned diagram tensions, debt and drift markers into parallel-implementation hypotheses. Sonnet workers verified each one at committed HEAD by symbol, using `git grep … HEAD` and `git show HEAD:<path>` and ignoring dirty working trees. An Opus adversarial reviewer re-read the decisive lines, changed severity or status where the evidence required it, and rejected or merged hypotheses. The run was ruflo swarm `swarm-1793554194775-k2wdr2` (hierarchical mesh: Opus leads, Sonnet workers). The anchor prefixes are kept exactly as the clusters gave them. `visionclaw:` and `project:` both mean VisionClaw. `agentbox:services/dream-engine/…` is agentbox's own dream-engine service, distinct from the `dream-engine:` repository. `WasmVOWL:` is a standalone checkout and `loom:` is the Loom repository; neither was pinned in this audit, so ABM-12 and ONT-09 rely on the worker's reading of them.

The assessment has these limits:

- Everything was read-only. No sibling repository was edited, checked out or stashed.
- Reachability is static. Call graphs come from grep and reading, and no runtime, integration or load test was run. Claims such as "always Err", "replay within 60 s" or "XR cannot pass the release gate" are source readings, not reproductions.
- Severity measures the consequence of disagreement between the paths, not exploitability.
- Deliberate parity guarded by a shared fixture is not counted as uncontrolled duplication. The guard is recorded instead.

**Status vocabulary.** CONFIRMED-LIVE means both paths are reachable in production. PARTIAL means one side is half-wired or only reachable under a flag or configuration. ONE-DEAD means one path is shipped and compiled but has no production caller. RESOLVED-SINCE-STAMP means HEAD has already fixed what the diagram describes.

**Merges.** These records are merged and shown once, in the table of the cluster that owns the first-named ID: VCS-10 / XR-01, VCS-01 / EST-01, VCS-09 / VCG-03, ONT-01 / ABM-07 / XR-02, ONT-04 / XR-03, ABR-04 / ABI-12, ABI-04 / ABR-10, ABM-02 / XR-11, EST-09 / XR-13 and FWP-02 / XR-09. A merged row takes the higher severity and the stronger status, and records any dissent.

## Cross-cutting patterns

These patterns recur across clusters and repositories. Fixing a pattern once retires several findings, so this is where consolidation pays most.

### P1. One NIP-98 contract, many verifiers and carriers

There are three Rust verifiers (VisionClaw `utils/nip98.rs`, solid-pod-rs, `nostr-bbs-core`) and one JS verifier on three Schnorr stacks, and they disagree on URL matching, body binding and replay:

- **VisionClaw has two verifiers in one binary.** `/pay` uses the weaker one: no replay cache, `req.uri()` origin-form and `None` body (VCS-10 / XR-01).
- **agentbox suffix-matches the `u` tag** with `endsWith` (ABI-09).
- **The forum and solid-pod-rs each call their own verifier "single source of truth".** solid-pod-rs trims trailing slashes and has GitLenient; the forum compares exactly (FWP-01).
- **Event-id serialisation is copied three times inside solid-pod-rs**, and the vendored vectors are never run (XR-14).
- **The website seed scripts carry 12 inline signers** (FWP-15).

Carriers have forked too. `/wss` accepts upgrade-time, post-connect and legacy messages, and the XR post-connect carrier cannot pass the release gate (VCX-01). Agent-event ingest is still gated by legacy sessions and an unconfined `?token=` (VCS-11). XR hand-serialises NIP-98 events (VCX-07).

The shared `nip98-tokens.json` is consumed only by agentbox and `nostr-bbs-core`. It has no URL-normalisation or body-binding vectors, and VisionClaw and solid-pod-rs never load it (ABI-09, XR-06). The forum/solid-pod-rs fork is partly justified by licensing: delegating would pull AGPL into an MIT/Apache crate. Accept that fork explicitly, and pin behaviour with shared vectors rather than shared code.

### P2. The ontology compiler fork and everything downstream of it

VisionClaw's `crates/vault` and `vault-core` are the pre-relocation copy of `ontomark-compile`. They are not dead. `ontology-publish.yml` still builds, certifies and publishes `ontology-latest`, and the server pulls that release into the pod at boot (ONT-01 / ABM-07 / XR-02). visionGraph publishes the site with ontomark v0.7.0. The same fork accounts for most of the ontology cluster:

| Fork effect | Findings |
| --- | --- |
| Public gate disagrees on `public: "true"` | ONT-02, ONT-06 (cf. XR-12) |
| Two persisted ontology stores, three possible class sets | ONT-14 |
| Two EL reasoners (whelk-rs fork vs whelk-el) | ONT-04 / XR-03 |
| NGG1 codec in three places; the cross-language guard skips | ONT-08 |
| An importer shells out to vault verbs that now exit 2 | ONT-07 |

The parity guards have quietly decayed. The ontomark golden was re-blessed after Supply Chains was added. `ts-reader-check.mjs` exits 3 because the visionGraph TS file it reads was deleted, so its test skips. The VisionClaw workflow comment says both sides use "the same binary", which is false at HEAD. Retiring vault (VC-60) is the single highest-leverage deletion in this report.

### P3. Key custody: one boundary, many direct readers

The identity port was meant to keep keys inside `ab-identity`, but only the pod NIP-98 op has a production client. About eight processes read keys directly (ABI-01), through several routes:

- the dead-writer `nostr.key.enc` envelope, a PBKDF2 of the management bearer token (ABI-02, S0);
- three role-secret precedence copies, of which dream-engine has drifted (ABI-04 / ABR-10);
- `VISIONCLAW_NOSTR_PRIVKEY` read raw, beside the `*_KEY_FILE` loader (VCS-14);
- five copies of HMAC child-key derivation (ABI-03).

Two related splits sit beside these:

- **Agent identity.** Two boot-time identity minters disagree on what "the agent's DID" means (ABI-11). A hand-built DID document lives beside solid-pod-rs `render_did_document_published` (XR-07).
- **Version skew.** `nostr-bbs-core` runs at beta.11 and beta.16 in one image (ABI-10).

Secrets backup also has a plaintext twin (EST-13). The only fully guarded pair in this area is the egress policy (ABI-13), and it is the model the others should copy: one table, one shared fixture consumed by both languages, and a CI register check.

### P4. Bespoke crypto formats beside trusted tooling

None of these is a hand-rolled curve primitive. All delegate the arithmetic to `node:crypto`, RustCrypto, WebCrypto or libsecp256k1. They break the "no bespoke format or envelope" rule:

| Finding | Format | Exposure | Fix |
| --- | --- | --- | --- |
| ABR-11 | Hand-encoded X.509/DER | Fallback only, fails closed | Delete; openssl at boot is the source |
| ABI-02 | PBKDF2(API key) plus AES-GCM key envelope | Reader only; no writer | Delete; route through the identity port |
| XR-05 | Four reductions of a tagged hash mod *n* | Live key derivation; KAT-guarded | One `Reduce<U256>`-backed helper |
| VCX-07 | Hand NIP-01/NIP-98 serialisation, hand base64 | Live, cross-checked against the `nostr` crate in tests | Use `base64` now; evaluate `nostr` at runtime |
| FWP-08 | `f1.` HMAC macaroon-lite | Live, but in a publishable crate | `publish = false`, or JWT |
| ABI-03 | Five copies of HMAC child-key derivation | Live default path is one copy | Call `nostr_bbs_core::keys::derive_subkey` |

FWP-06, the WebCrypto at-rest envelope, is duplicated but not hand-rolled.

### P10. Identifier minting outside the declared grammar

agentbox Rust services mint `urn:agentbox:*` with `format!`. There are two `mint_activity_urn` functions, one random and one sha256-12 (EST-05). VisionClaw crates mint `urn:visionclaw:execution:inference-…`, which the canonical parser rejects (EST-06). In both repositories the declared minter (`uris.js` KINDS, `src/uri`) is guarded only for the federation crossing map, not for the mint grammar.

### P11. Embedding and memory pipeline copies

There are twelve hand-copied Xinference embedders, and only `ruvector-mcp.cjs` runs the ADR-2019 identity probe (ABM-02 / XR-11). Three other paths write to or search the shared table outside `memory-tools`:

- the external-pg adapter (ABM-01);
- the dream-engine row shape (ABM-03);
- `ruvnet-brain` search (ABM-11).

A model swap that keeps 384 dimensions would land vectors from a different space without detection. XR-11 also claims that the workspace note about the CLI bypassing the embedding pipeline is wrong, because `ruflo-memory-cli.cjs` writes through `memory-tools.js`. The workspace note names the `claude-flow memory *` CLI, which may be a different tool, so this is recorded as the reviewer's claim and not as a confirmed correction.

## Suggested consolidation order

These are ordered by value, meaning risk removed per unit of change. The first three are small patches.

1. **VCS-10 / XR-01: route `/pay` through the canonical NIP-98 verifier.** Use replay, the absolute URL and body binding on the value-moving POSTs. This is a one-function change in `pay_handler.rs`, plus loading `nip98-tokens.json` in a VisionClaw test.
2. **ABI-05: remove the structural-accept fallback from `_verifySig`**, so the default governance gate fails closed, and inject `verifyEvent` in the test doubles. The single-ingress consolidation can follow.
3. **FWP-04: clear the KV `nip05:` entry in admin member-delete** now, then move well-known resolution onto D1.
4. **ONT-01 / ABM-07 / XR-02: retire the vault compiler.** First switch `ontology-publish.yml` to ontomark and make `vault-core` `is_public` strict (ONT-02, ONT-06). Then delete the vault build and certify paths and `vault-core`. This retires or simplifies ONT-02, ONT-06, ONT-08, ONT-14, ONT-04 / XR-03, ONT-07, ABM-12 and ABM-13 in one programme.
5. **ABM-01 with ABM-02 / XR-11: one memory write contract and one embedder.** Stop the external-pg adapter writing vectorless rows over governed ones, then make every writer use the identity-checked embedder.
6. **VCS-15 and VCS-14: fix the two VisionClaw identity and settings splits.** Serve the API-keys GET from `NostrService`, and make the bridge and bead publisher use `load_panel_secret`.
7. **Key custody (ABI-02, ABI-04 / ABR-10, ABI-01, ABI-03).** Delete the `nostr.key.enc` reader. Share `role_secret.rs` with dream-engine behind a precedence fixture. Move direct key readers onto the identity port under isolation.
8. **Bespoke-format quick wins (ABR-11, EST-13, FWP-08).** Delete the DER fallback, replace the plaintext secrets ZIP with `agentbox-secret-backup`, and stop the `f1` token crate from being publishable.

10. **Estate NIP-98 and zone-grant vectors (ABI-09, FWP-01, VCX-01, VCS-11, XR-14, FWP-07).** Extend the shared fixtures with URL-normalisation, body-binding and grant-rejection cases. Consume them in every repository, and fix agentbox `endsWith`.
