# Agentbox, Loom and RuVector consumer audit — 2026-09-07

The external review correctly identifies shared-UID custody and incomplete cross-system governance, but it confuses several historical defects with current source behaviour. The learning recorder grades structured transcript results; the seccomp gate now protects every established denial; optional break-glass bounds exist; and the latest recorded HNSW incident was attributed to parallel building. These corrections do not establish deployed isolation, complete telemetry or cross-store erasure.

## Findings

### AB-AUD-01 — The custom seccomp profile does not stack automatically with Docker's default

`docker-compose.yml` explicitly selects `config/seccomp-agentbox.json`, whose `defaultAction` is `SCMP_ACT_ALLOW`. Both its commentary and `scripts/ci/check-seccomp.sh` describe a supplemental layer over Docker defaults. Docker states that an explicit `--security-opt seccomp=...` overrides the default profile ([primary Docker documentation](https://docs.docker.com/engine/security/seccomp/)). Thus AB-16.2 overstated the effective source policy. Host capabilities, namespaces, mounts, no-new-privileges and any independently installed filters remain separate controls; this observation alone is not proof of an exploitable container escape.

The gate itself now validates all 46 unconditional syscall denials and the AF_ALG argument tuple. This audit ran it successfully. The old six-name-only gap is closed in source. Acceptance: correct upstream comments and architectural policy, capture the selected deployed profile and independently test intended denials in an isolated disposable container. Do not read a JSON gate as a running-kernel attestation.

### AB-AUD-02 — Shared UID and optional break-glass bounds are different custody limits

`management-api/lib/agent-identity.js::loadOrMint` writes owner-only keys. Profile wrappers separate HOME/configuration, but supervised programs share `devuser`; mode 0600 cannot isolate same-UID peers. No per-process isolation was established. This corroborates the external review's custody concern without reading real keys or asserting compromise.

`config/nip98-proxy/proxy.mjs::verifyIdentity` calls `breakGlassNotExpired` and `breakGlassScopeAllows` after token comparison. Unset expiry and unset scope allow unbounded use; malformed configured expiry fails closed. Acceptance/refusal logs carry a fingerprint and in-process counters. AB-16.6 previously contradicted itself by drawing these checks then asserting they did not exist. ADR-2027's full lifecycle remains proposed: optional controls and logs do not establish required configuration, durable audit, custodians or revocation across caches/restarts. Acceptance: synthetic expired/wrong-scope/revoked fixtures plus durable use receipts and a documented custody boundary.

### AB-AUD-03 — Learning failures are a coverage problem, not LLM error-text guessing

`config/hooks/lib/trajectory-util.cjs::gradeResult` uses transcript `tool_result.is_error`; absent flags and interrupted calls return null. `trajectory-recorder.cjs` runs at Stop/SubagentStop and rejects the PostToolUse route. It does not infer success from an LLM omitting expected failure prose. The newer recorder retains its watermark on missing pg and connection failure; content-addressed IDs support retries. Usage identity and queue metadata address earlier accounting gaps.

The actual limits remain: non-Bash work, ungradeable/skipped results, crash-before-Stop and missing future Stop events are not a complete failure denominator. The transport does not prove delivery merely by scheduling an emit; no recorder-to-dashboard workflow or consumer usage deduplication was exercised. Three selected Jest suites passed 57 tests, covering trajectory grading, learning closeout and RuVector gates. An initial attempt under Node's test runner failed because these suites require Jest globals; rerunning with their actual Jest runner passed.

### AB-AUD-04 — Cross-store erasure, index tombstones and recall are separate contracts

Agentbox ADR-2060 remains proposed: a Pod memory deletion has no durable reverse-tombstone consumer into primary RuVector memory. The existence of an HNSW tombstone is not that protocol. Local RuVector `crates/ruvector-postgres/src/index/hnsw_am.rs::hnsw_bulkdelete` marks deleted nodes; its presence does not establish how the deployed extension handles churn or whether that causes recall loss.

Agentbox ADR-2018's later closeout attributes the measured defect to parallel index building: serial rebuilding is reported to restore self 189/200 and true 115/120. The checked-in `docs/estate-closeout/2026-09-05/adr-2018-recall-gate-verdict.json` still records the earlier failure (164/200 and 96/120). These are different observations, not interchangeable evidence. No new live recall run or SQL operation was performed here. The diagrams now name serial as well as non-concurrent rebuilding and label the results historical. Acceptance: a fresh integrity-bound receipt for the deployed model/corpus/index and a durable, replayable erasure acknowledgement protocol with recovery tests.

### AB-AUD-05 — Application governance is route-specific

`management-api/lib/action-plane.js::dispatchTaskSpawn` refuses when journal/events plumbing is unavailable, then executes task spawn through its pipeline. Spawn is deliberately classified `local`, so the fast path does not require an extra human approval receipt. ADR-2041 is partial; ADR-2071 still proposes journalling the nightly SSH/model/push/publication path. Neither establishes mediation of every tool or arbitrary same-UID shell process. ES-05 now draws this boundary explicitly. Acceptance: enumerate side effects and attach each to an enforced gate or explicit residual-risk disposition; prove replay, refusal and approval handling for the actual route.

### AB-AUD-06 — Loom server identity exists, but the Agentbox consumer does not verify it

Loom's Rust `crates/loom-facade/src/routes/mod.rs` exposes `/loom/generation`; `bundle.rs` verifies generation material. Agentbox `mcp/servers/lib/ontology-retrieval.js::selectBackend` takes generation from configuration and its transport calls `/loom/search` and `/loom/sparql`, without reading that identity endpoint. ADR-2075 needs its server-absence premise narrowed: client attestation is missing even though a local server implementation exists. This audit did not identify the binary running at an external endpoint.

Loom `crates/loom-graph-oxigraph/src/lib.rs` loads Turtle into the shared default graph. The Agentbox Loom expansion omits GRAPH clauses, so asserted/inferred scope is still not backend-enforced (ADR-2073). `scripts/loom-retrieval-recall-harness.mjs` and `mcp/servers/ontology-distill.js` are absent: ADR-2076 and ADR-2074 remain proposals. Scaffold/chat benchmarks are not measurements of this client search/SPARQL path. ADR-2070 also resolves the older ingress/egress conflation: a named raw-model egress route does not contradict the AoE ingress identity door.

### AB-AUD-07 — Staged source must not become a live claim

ADR-2081 source contains `engine.rs::annexe_subpath`, `runner.rs` pipefail command construction and `gate.rs` no-candidate handling. Existing AB-23 diagrams already document the mechanics; the audit adds the activation qualification. A supervised Nix-store binary does not change when a working-tree source file changes. Acceptance requires rebuilt image identity and the loaded process binary, then an evaluator run demonstrating the corrected receipt path. Likewise ADR-2077's byte-identical-when-off claim requires actual closure/runtime comparison, not a manifest parser or source fixture.
