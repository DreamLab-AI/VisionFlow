# Audit wave 4, coverage A: prose-sanitiser and diagram-ir

**Outcome.** I gave all thirteen uncited components a disposition: twelve are **assessed** and one, the diagram-ir integration tests, is **out-of-scope**. None is covered-elsewhere, because the only corpus text about either repository, ES-90 (`docs/diagrams/estate/90-evidence-and-supporting-repositories.md:95-96`), names the crates and binaries without describing what they do. So the sixteen binaries agentbox puts on every agent's `PATH` (thirteen from prose-sanitiser, three from diagram-ir) have no description in the corpus, which is the largest gap here (COV-A-F11). Agentbox builds prose-sanitiser from tag `v0.1.5`, which resolves to `b261f65`, and `git diff --stat v0.1.5 20ad8b3` changes only `docs/dream-cycle/LEDGER.md`, so the audited code is the code that ships. Agentbox builds diagram-ir from `v0.1.0` (`16b1f84`), four commits behind the pin, and the 865-line `semantic_review` module is not shipped (COV-A-F1). The code is careful overall: size caps, zip-bomb budgets, DNS-rebind pinning, loopback-only rewrite endpoints and argv guards are all present and cited below. Of the eleven findings, ten are low and the corpus gap is medium. They cover claims in documentation that the code contradicts, unbounded memory on one draw.io path, script and template lookups relative to the current directory, and IPv6 gaps in the SSRF filter. Evidence class: **source tracing at the pinned revision** (prose-sanitiser `20ad8b33ab7d`, diagram-ir `15cba163da70`, agentbox `c57d9c0508f4` for the consumer side), with no builds, tests or runtime observation.

### Do the existing topics still describe what these repositories are for?

- **ES-90.4** cites `prose-sanitiser/Cargo.toml:18` at `b261f65`. Line 18 is still `members = [` at `20ad8b3`, and the seven members are unchanged (`Cargo.toml:18-26`), so the citation holds at the pin. "Tool capability, not proof every publisher invokes it" (ES-90 line 95) is still accurate.
- **ES-90** describes diagram-ir as "diagram extraction and self-check binaries" (line 96). That is still what ships. `semantic_review` is library-only and unshipped, so ES-90 can leave it out for now. That changes once a consumer wires up the System One transport, because that would create a new wire contract with whatever serves `/v1/systemone`.
- **VF-03** (`docs/diagrams/visionflow/03-estate-health.md:54-55`) labels both repositories "published crate". That holds for diagram-ir and for six of the seven prose-sanitiser crates. `prose-sanitiser-server` is not published (`crates/server/Cargo.toml:15`).
- **11-publishing-axis** (line 158) says both repositories are rostered "with NO diagram area in this tree". That is still true; see COV-A-F11.

### Material the corpus misses

- Agentbox puts thirteen prose-sanitiser binaries and three diagram-ir binaries on every agent's `PATH`, with no gate (`agentbox:flake.nix:1825-1839`). No topic records this supply path.
- The four torch harnesses (`score_synthid.py`, `clean_ctrlregen.py`, `markdiffusion_harness.py` and `detect_text_watermark.py`) stay in Python under `agentbox:skills/prose-sanitiser`, and Rust code in the prose-sanitiser repository runs them (`agentbox:lib/prose-sanitiser.nix:19-27`; `prose-sanitiser:crates/media/src/image/harness.rs:27-36`). No topic records this runtime coupling between the two repositories.
- No topic records the egress policy of `rewrite-text`, which is the estate's only path for sending prose to an LLM for rewriting. It allows only loopback endpoints by default, `--allow-remote` lifts that, and it never follows redirects.
