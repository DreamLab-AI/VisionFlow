# Drag holds, release evidence and visual-budget refresh

The drag acceptance script can report that a node rejoined physics when the peer kept it pinned and sent no post-release positions. A fresh localhost negative control made all five checks pass. This invalidates the script's release/settle conclusion for that case; it does not demonstrate a failure in the deployed backend.

This batch assesses ADR-2169 section by section at VisionClaw `531df5ef74453a2ed320bff968c203a9b91faed7`, and refreshes the changed ADR-2167 annex against its earlier whole-document assessment. [Pinned source, tests and reproduction instructions](evidence/2026-11-01/drag-contract/README.md) separate actual registry tests, a model of the orchestrator and the intentionally wrong WebSocket peer. No production server, graph or headset was contacted. ADR-2140 is context; ADR-2143, ADR-2166 and the full ADR-2172 interaction chain remain outstanding.

## Findings

| ID | Evidence | Consequence and acceptance requirement |
| --- | --- | --- |
| DH1 — false release acceptance | The unchanged script snapshots the dragger's held position at line 320, then compares it with the observer's latest position at lines 359–364. The local peer gives the dragger neighbour updates while its held-node sample remains stale; the observer sees the held node move during the drag. On release, the peer keeps the pin and sends no further positions. The script reports 150 units of released-node travel, zero settle milliseconds, zero post-release frames and exits 0. | A cross-client difference is not post-release displacement. Use one observer's ordered, generation-bound samples before and after a confirmed release; require evidence that samples postdate release. Include this frozen-peer case as a negative test. A free node already at equilibrium may legitimately move zero, so movement alone is also insufficient to prove release state. |
| DH2 — silence is treated as rest | `lastMotion` returns the release time when no later motion exists (`drag-physics-acceptance.mjs:220–234`). The script does not require fresh post-release data or a liveness/state receipt for its rest check. | No delivery, a disconnected/stalled observer and a settled graph can look identical. Report an inconclusive observation until stream liveness and an authoritative state or sufficiently fresh samples distinguish them. The negative control confirms the missing gate; it does not measure a real outage. |
| DH3 — ownership differs between GPU and orchestrator | `release_holds` sends a node-only `Released` notification before consulting the GPU (`position_updates.rs:259–274`). The registry correctly ignores a previous owner's release; the orchestrator removes the id regardless (`physics_orchestrator_actor.rs:1189–1195`). | This is already disclosed in ADR-2169. The fresh probe invokes the actual registry and explicitly models the inspected HashSet operations; it is not an actor integration test. Reconcile orchestrator state from accepted ownership transitions, including expiry, and test two holders, takeover, stale release and disconnect with equilibrium pause enabled. Current deployment settings are not assumed. |
| DH4 — expiry is an operation, not a wall-clock guarantee | The actual registry readmits a hold arriving after `release_holder`; it expires only when `expire` is called and age is strictly greater than five seconds. `ComputeForces` invokes expiry after halt, overload, in-flight-compute and missing-context early returns (`force_compute_actor.rs:1783–1859,1900–1913`). | The backstop mitigates reordering while computation proceeds. It is not a connection tombstone or independent timer. Test delayed holds, disconnects and suspended computation before claiming a bounded release lifetime. A generation or closed-holder barrier would reject obsolete work instead of relying only on expiry. |
| DH5 — timeout wording is tighter than the polling schedule | Socket checks are scheduled at `drag_timeout_ms + 100` and reschedule by that full interval (`position_updates.rs:333–340,635–646`). With a 2 s timeout, an update just before a check can remain held until nearly another 2.1 s elapses beyond its timeout. | This is source-derived timing, not a measured scheduler bound. Specify a minimum inactivity threshold plus check latency, or schedule from the last update's expiry. Actor stalls can add further delay. |
| DH6 — required position is permissive | `parse_position` defaults missing or nonnumeric axes to zero before applying finite/range checks (`position_updates.rs:198–213`). The protocol table calls for a position. | Authentication and finite bounds exist, but malformed coordinates can become an origin-directed move. Decide whether partial coordinates are a supported API; otherwise reject malformed shape explicitly and test missing, string, null and partial axes. This is source evidence, not a production exploit test. |

A second measurement limit is independent of DH1: the script selects the nearest nodes by position by default, rather than reading graph adjacency (`:266–285`). Their movement does not specifically establish spring-neighbour response. Supply verified linked ids and record their graph generation for that experiment. `firstMove` also scans the entire log after the first update, so its “while held” check has a latency bound but no release-time bound. A sufficiently short drag can count post-release motion as in-hold response.

## Visual-budget decision refresh

The earlier [ADR-2167/2165 section assessment](2026-11-01-xr-budget-and-engine-qualification.md) remains the detailed baseline. Across all seven ADR-2167 governed paths, `75b72416b` to `531df5ef7` changes only nine lines in `spatial_environment.gd`. The allocator, governor, cost table, budget pass, benchmark and GPU probe are byte-identical. Existing XB1–XB5 findings remain open; their fixtures are retained historical runs, not fresh performance results.

The new annex changes the focus marker from one grabbed id to the first held hand and asks `focus_frame_for` for that node's volume transform. Source tracing finds `_any_grab_id` left-first and `focus_frame_for` selecting a held volume, a targeted volume or GraphRoot (`graph_scene.gd:171–172,203–209`). This supports the transform-selection part of the annex.

Coordinate provenance still needs a differentiated-stream test. `SpatialEnvironment` obtains coordinates from the primary `_binary_client` (`:92,107`) and applies the selected volume transform (`:108–111`); `_begin_grab` obtains coordinates from that volume's connection (`graph_scene.gd:3415`). If those connections carry different positions for an id, selecting the right transform alone cannot select the right point. `test_label_pool_and_focus_marker_follow_the_volume_of_the_node` checks transforms, not the full marker's coordinate supplier. This is a source-level conditional gap, not a reproduced headset misplacement. Add a test with distinct positions in two connection buffers before treating the focus marker as fully qualified across volumes.

That bounded assessment restores ADR-2167's document binding with its open findings intact. The two other stale assessments, ADR-2143 and ADR-2166, remain stale pending their broader source review.

## Comparisons and utility

D3 distinguishes fixed coordinates (`fx`/`fy`) from free simulation state: clearing those fixed values releases a node, while restarting and alpha controls govern reheating. This is a useful interface comparison for separate “hold”, “pin” and “resume” actions; D3's integrator is not evidence for VisionClaw's FA2 response or timings. [D3 force simulation](https://d3js.org/d3-force/simulation).

Yjs keeps awareness outside the persistent document and removes a participant's awareness on going offline. The transferable distinction is temporary interaction presence versus persistent authored state; its awareness mechanism is not a substitute for server-authoritative node ownership or a proof of release ordering here. [Yjs awareness](https://docs.yjs.dev/getting-started/adding-awareness).

For users, show the current holder, an explicit pin indicator, connection health and effective interaction speed. Evaluate two people grabbing the same node, one disconnecting, the remaining person releasing, and a pinned node surviving that cycle. Measure task completion, accidental persistent anchors, conflicting hand feedback, observer freshness and actual settle time. Before a device study, make the acceptance script reject the frozen-peer negative control and distinguish an inconclusive stream from a settled graph.
