# Dream annexe identity and evaluator receipt audit

Mirroring repository depth fixes ordinary relative dependencies, but it does not bind the annexe to the captured baseline. Dispatch resolves HEAD again, and a configured outside sibling with the same leaf name can overwrite target files. Evaluator status also has limits: the local and SSH runners classify some identical faults differently, while a no-patch ACCEPT still creates an operator alert despite the ADR's contrary clause.

This pass assesses ADR-2081 section by section and updates AB-23.11–14. Ten other AB-23 panels remain queued. Earlier [candidate/evidence](2026-11-01-dream-candidate-and-evidence.md), [migration](2026-11-01-dream-migration-and-provenance.md) and [adapter controls](2026-11-01-dream-adapter-controls-and-egress.md) findings remain open. Owner source and ADR statuses are unchanged; neither source inspection nor local execution establishes activation on the supervised image.

## Evidence and limits

Agentbox remains at `9dfc27b16e82e9786535a55e790710493dd51fdf`, and dream-engine at `815f963b1cbd6999e78144ce5475005ae1dd1d8e`. All inspected inputs in the [source manifest](evidence/2026-11-01/dream-receipts-source-manifest.json) match their existing diagram pins byte for byte. The previous migration pass also bound the consumed crate archives and Rust sources to the adapter lockfile.

[Five focused tests pass](evidence/2026-11-01/dream-receipts-probes-final.log), using the [committed probe source](evidence/2026-11-01/dream-receipts-probes.rs) appended to a clean export of the host's night fixture. They exercise both actual runner implementations, actual archive/extraction functions and one actual engine night. SSH/SCP executables are local substitutes that refuse non-fixture hosts; the model is scripted, the forge records requests without publishing, and night-level integrations are disabled. Empty memory endpoints fail before any database/network use. No live annexe, model, forum, daemon or production repository is executed or changed.

These tests assert current observations, including defects. Passing them does not mean the defects are fixed. Eleven existing host tests are filtered out; their preceding pass remains evidence for unchanged paths. A first five-test run passed, then explicit checks for producer failure through a successful tail and exactly one Unproven veto were added and the focused suite rerun. [Reproduction notes](evidence/2026-11-01/dream-receipts-reproduction.md) describe the isolation and commands.

## Comparison and utility

[GNU Bash's manual](https://www.gnu.org/software/bash/manual/bash.html) defines pipeline status under pipefail in terms of the rightmost nonzero command. That supports the corrected diagram; the local executable probes additionally demonstrate the actual wrappers' behaviour.

[Bazel's hermeticity documentation](https://bazel.build/basics/hermeticity) separates isolation from source identity and ties reproducibility to explicit tool and dependency inputs. [Reproducible Builds' environment guidance](https://reproducible-builds.org/docs/perimeter/) calls for recording tools, versions and relevant environment assumptions. These are useful comparisons for the annexe boundary: a mirrored directory layout and a target commit label are only part of a reproducible experiment.

Dream-engine's user-facing proposition remains evidence-backed repository experiments. A useful next deliverable is a portable experiment-input receipt covering target commit/tree, sibling identities and destinations, evaluator commands, tool versions and execution causes. Measure whether the same receipt can be rerun on a second clean worker, whether source changes after freezing are detected, and whether operators can distinguish a rejected patch from broken infrastructure without reading raw logs. This is an inference from the observed gaps and comparison documents, not a benchmark, adoption claim or recommendation to replace the engine with a build system.
