# Browser XR input, XR memory cloud and Codescape panels

I traced all 37 panels of VC-37, VC-38 and VC-39 line by line at VisionClaw `86cdd7635`, agentbox `c57d9c050` and codescape `13e056d`. Twelve are accurate, twenty corrected, five accurate with limits, and none inaccurate-unfixed. The most important finding is in VC-37: the SpaceMouse path the topic drew as live is not mounted. The canvas mounts `SpacePilotSimpleIntegration`, which drives the camera with hard-coded tuning. The `useSpacePilot` hook and `SpacePilotController` behind VC-37.4, VC-37.5, VC-37.9 and VC-37.10 have no importer, so stored SpacePilot settings change nothing on screen. The same pass found that `platformManager.ts` and `remoteLogger.ts` are imported by nothing. That leaves no browser XR capability probe and no XR telemetry in the bundle, contradicting ADR-2081's reason for keeping the probe. VC-38 and VC-39 held in substance. Their corrections are re-resolved lines, one narrowed Drift and one stale verification sentence.

VC-37.1 and VC-37.3 carried mislabelled line numbers in files unchanged since their stamp (`platformManager.ts:97` labelled as `initialize`, `:164` as `detectPlatform`). Strict cite-check passed them, because it proves a line exists at the revision, not that it holds the label.

## Findings

**W3K-01: the mounted SpaceMouse path ignores SpacePilot settings (VC-37.4, .5, .9, .10).**
- **Trigger:** a user or script stores `settings.visualisation.spacePilot` (`client/src/features/settings/config/settings.ts:596`).
- **Consequence:** nothing reads it. The canvas mounts `SpacePilotSimpleIntegration` (`client/src/features/graph/components/GraphCanvas.tsx:500`), which uses a literal config (`SpacePilotSimpleIntegration.tsx:29-38`). The only reader and writer is `client/src/features/visualisation/hooks/useSpacePilot.ts` (`:58-59`, `:211-215`). No file under `client/` imports that hook. `SpacePilotController` is imported only by the hook (`useSpacePilot.ts:4`).
- **Evidence:** `git grep` at `86cdd7635` for `hooks/useSpacePilot` and `SpacePilotController` over `client/` returns only the two files themselves.
- **To close:** point the settings at the mounted integration, or delete the hook, the controller and the settings field. Pin whichever is chosen with a test that a stored deadzone changes the integration's behaviour.

**W3K-02: the platform store, its WebXR probe and the XR telemetry module are unreachable (VC-37.1, .2, .8).**
- **Trigger:** none; this is the import graph.
- **Consequence:** no file under `client/` imports `client/src/services/platformManager.ts` or `client/src/services/remoteLogger.ts`. The probe (`platformManager.ts:85-152`) never runs. `remoteLogger`'s own probe and its load-time `logXRInfo` (`remoteLogger.ts:271-290`, `:319-324`) never ship.
- **ADR conflict:** ADR-2081 kept the store probe "because `remoteLogger` reports those as telemetry" (`docs/adr/ADR-2081-remove-dead-browser-xr-surface.md:36-39`). `remoteLogger` never reads the store (`remoteLogger.ts:273`), and neither module is loaded. ADR-2081 is `activation_status: live` (`:7`), so its stated rationale is contradicted at the pin.
- **Also corrected:** VC-37.1 said `AppInitializer` calls `initialize()`. The `initialize()` in `AppInitializer.tsx:130` is the settings store's.
- **To close:** amend ADR-2081. Either delete both modules, or import the telemetry and have it read the store.

**W3K-03: the paired-device loop stops at the first candidate (VC-37.4).**
- **Trigger:** two supported devices are paired and the first fails to open.
- **Consequence:** `openDevice` catches and logs its own error (`SpaceDriverService.ts:178-180`), so the loop's `catch` never fires. `opened = true` after the first candidate (`:107-120`), and the second device is never tried, despite the comment at `:107`.
- **To close:** rethrow from `openDevice`, or return a success flag. Test with a stub device whose `open()` rejects.

**W3K-04: the camera integration does not seed its connected state (VC-37.4).**
- **Trigger:** `SpaceDriverService` opens a paired device during its import-time `initialize()` (`:320-323`) before the canvas mounts the integration.
- **Consequence:** `isConnected` stays false (`SpacePilotSimpleIntegration.tsx:40`, `:95-97`), so `useFrame` returns early (`:166`) until a reconnect. The Status hook avoids this by seeding from `SpaceDriver.isConnected()` (`control-center/status/useSpacePilot.ts:73`).
- **Limit:** whether the open beats the mount is a runtime race this trace cannot settle.
- **To close:** seed from `SpaceDriver.isConnected()` on subscribe, as the Status hook does.

**W3K-05: head-parallax nudge mode compounds the projection each frame (VC-37.6).**
- **Trigger:** `cameraMode` is anything other than `asymmetricFrustum`.
- **Consequence:** `camera.projectionMatrix.multiply(...)` runs on every tracked frame (`HeadTrackedParallaxController.tsx:62`) without a rebuild. The only other `updateProjectionMatrix` calls run on a canvas size change (`GraphCanvas.tsx:181-191`) and on an event-driven camera fit (`useCameraAutoFit.ts:66`, `:146-160`), so between those events the offsets compound. Stopping tracking in this mode does not reset, because the reset branch needs `camera.view` (`:66-68`).
- **Limit:** not observed at runtime.
- **To close:** rebuild the projection before applying the nudge, and test that the matrix after N frames equals the matrix after one.

**W3K-06: smaller VC-37 items, recorded in place.**
- The `connect` listener is an anonymous closure that `destroy()` cannot remove (`SpaceDriverService.ts:132-140`, `:307-313`). This is latent, because nothing calls `destroy()`.
- `useApplicationMode` has no consumer, and every layout branch is identical (`ApplicationModeContext.tsx:74-95`, `:114`).
- `project.godot:57` selects the Mobile renderer for mobile exports beside the forced Compatibility renderer (`:56`).
- The agent overlay that read `NodePositionContext` (`BotsVisualization.tsx`) was retired in `923f9ae83`. Its one reader now is `EmbeddingCloudLayer.tsx:49`, `:85-90`, and the publish sites are `GraphManager.tsx:424` and `:81`. VC-37.7 is redrawn to match, and the deleted file is removed from `sources:`.

**W3K-07: the VC-38.7 Drift was overstated.**
- **What the topic said:** `docs/XR-client.md` omits `sidecarTotal` and `sidecarAgree`.
- **What the doc has:** the inline frame shape omits them (`docs/XR-client.md:492-493`), but a separate bullet documents both fields and the consistency rule (`:531-534`). It already did at the previous stamp (`8692b12:docs/XR-client.md:521`).
- **Fix:** the Drift is narrowed to the one-line shape summary.

**W3K-08: the generator advisory on VC-37.9 is settled.** `SpaceDriverService.ts:163` is `inputCount: c.inputReports?.length` and does not hold the `device.open()` label. `device.open()` is at `:159`, and the topic is corrected. A new advisory on VC-37.6 (`useHeadTracking.ts:41-44`) was checked by hand. Those lines are the catch block that sets the cited error message, so the label holds.
