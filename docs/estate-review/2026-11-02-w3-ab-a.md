# Agentbox flake, boot and manifest-gate topics

I assessed all 47 panels of agentbox topics AB-01 (Nix flake composition), AB-02 (boot sequence and readiness) and AB-05 (manifest gates and the `agentbox.sh` CLI) by source tracing at agentbox `c57d9c0508f4`, and restamped all three from `6500582dfae2` (120 commits earlier). Result: 35 panels corrected, 9 accurate, 3 accurate with limits, 0 inaccurate and unfixed. The most important finding is that the topics still described two boot behaviours the pin has removed. The vault resolver no longer keeps or clears a legacy `ONTOLOGY_PAGES_DIR` override, because `VAULT_*` is now the only path authority. The RuVector Postgres password is no longer substituted into a claude-flow config template or exported as `RUVECTOR_PG_CONNINFO`; it now lives in one 0600 file. Both generator advisories (AB-01.3, AB-01.5) were real defects and are fixed. Many other corrections fix citations that were already wrong at the old stamp, not drift.

## Findings

**1. The vault resolver dropped the legacy path tier.** *Trigger:* the pin removes the three-tier precedence block and every `ONTOLOGY_PAGES_DIR` / `AGENTBOX_VAULT_LEGACY_PATHS` branch from `_ab_vault_resolve`. *Consequence:* AB-02.1, AB-02.14 and AB-05.4 described retain/clear branches and an enabled-vault override that no longer exist. *Evidence:* `config/entrypoint-unified.sh:77-84` (the new single-authority comment), `:91-96` (the disabled branch now just returns), `:1148` (`ONTO_PAGES="${VAULT_PAGES:-}"`), `docs/BASELINE-container.md:304` (now records the issue as resolved on 2026-10-31). The management-api view changed too: the `pages` default is now `.`, meaning the vault root (`management-api/lib/system-manifest.js:526-533`). *Closed:* the panels were redrawn; AB-05.4's divergence is now marked resolved.

**2. RuVector Postgres credential custody replaced the old password paths.** *Trigger:* `_ab_pg_credential_prepare` writes `RUVECTOR_PG_PASSWORD` once to `/run/secrets/ruvector-pg/password` (0600, devuser), exports only the public parts and `RUVECTOR_PG_PASSWORD_FILE`, then unsets the password and any conninfo (`config/entrypoint-unified.sh:473-507`). A scrub pass then removes stale conninfo and passwords from persisted configs on every boot (`:3829-3987`). *Consequence:* AB-02.3 still showed a `sed` substituting the password into `~/.claude-flow/config.json`, which is gone (`:1469-1472`; the flake template was also removed). AB-02.3's runtime-env note listed `RUVECTOR_PG_CONNINFO` (now `:4010-4014` export the parts). AB-02.6 said `dream-engine` inherits `RUVECTOR_PG_CONNINFO` from PID 1 (`flake.nix:2893-2897` now says it reads the file). *Closed:* all three panels corrected. Whether the scrub actually rewrites existing files is a runtime question I did not test.
