## Findings

Recorded as `remediation/audit-wave1-2026-11-02.json`, AW1-01 to AW1-11. The
lead re-read the cited code for AW1-01, -02, -03, -04, -07 and -09; the others
rest on one worker's report.

The two that matter most:

- **AW1-02: the SP-GIT-02 repair is not what agentbox ships.** agentbox pins
  solid-pod-rs `76ab7aab` (`lib/solid-pod-rs.nix:58`), which does not contain
  Commit A. The repair exists on local main only.
- **AW1-09: a trust boundary loom decided and VisionClaw does not enforce.**
  ADR-135 D7 ("verify signatures where trust is consumed", line 358) requires
  a BIP-340 distiller envelope checked against an allow-list at the
  `/derived` write door, and says generic `power_user` must not suffice.
  VisionClaw's door checks `power_user` and nothing else
  (`ontology_derived_handler.rs:188`).

Also confirmed by the lead: the mirror ignores the operator's relay policy and
so refuses agentbox's default loopback relay (AW1-01); a library-level `iat`
window that can never fire (AW1-03, not wired into the server); a public
unverified event-store write (AW1-04); and a 5xx logger registered innermost,
so guard-level failures go unlogged (AW1-07).

ADR-135 is internally inconsistent about its own numbering: its implementation
map (line 34) labels D7 as the server-side SPARQL clamp, while the decision
body's D7 (line 358) is signature verification.

One correction to this session's earlier report: an owner's smart-HTTP push
into a mirror is refused with 403, not 409. Only forge writes return 409. The
mirror publication report is corrected.

## Cross-vendor check

Codex (`gpt-6-astra`, stdin bundle, no tools) spot-checked six claims, then
two again with fuller evidence. Outputs: `audit-wave1-codex.txt` and
`audit-wave1b-codex.txt`.

**Result: partial.** No claim was refuted on the evidence shown. In every
sample Codex confirmed the core mechanism: `Mirror::new` selects
`DefaultSsrfCheck` while announce gets `OperatorRelays`; the `iat` comparison
cannot fire; the derived-write route applies only `power_user()`; Control
bypasses after a base grant; `_tick_links` runs on each tick. Its "partly"
verdicts are about context the bundle did not include.

Two samples failed because of the lead's bundling, not the claims:

- Sample 3 was first judged against the wrong "D7" (the implementation map at
  line 34). Re-read against the decision at line 358, the claim holds.
- SP-10.1 was first shown the wrong server lines; the rerun omitted the
  `nip98.rs` and `Cargo.toml` citations. On what was shown, five nodes are
  supported, I6 correctly shows a broken invariant (which the panel says), and
  two organising labels (SUR, N2) make claims they do not cite. N2's claim
  that every invariant maps to a named fixed bug is uncited; it is recorded
  here as a debt on SP-10.1, not fixed.

This is therefore a partial cross-vendor spot-check, not an independent
review of the wave.
