# agentbox sidestr, custody, mesh and media topics

I assessed all 28 panels in agentbox topics AB-33 to AB-38 by tracing source at agentbox `c57d9c0508f4`, nostr-rust-forum `c39f41f104b1` and sidestr-rs `d8ace3aad2f2`. Results: 6 accurate, 20 corrected, 2 accurate-with-limits, 0 inaccurate-unfixed. Every topic is restamped to the agentbox pin and passes the strict gate. The most important finding is that AB-33.8 overstated what CI enforces. The licensing rule's diagram cited lines about `dream-engine`, not sidestr. The licensing doc says `check-crate-licensing.sh` enforces the sidestr consumption rule, but the gate only checks that each `services/` crate carries the licence texts it declares. Nothing checks dependencies, and nothing enforces "crates.io only". Two more substantive corrections: the kind-38420 account binding, which AB-34 and the sidechain README listed as unbuilt, is built in `management-api/lib/sidestr-spend-key.js`; and since ADR-2164 amendment 2, `/run/secrets` holds a devuser-owned directory outside the role plan in both modes (AB-36.3). Most other corrections re-resolve citations that drifted when `agentbox.toml`, `flake.nix`, `entrypoint-unified.sh`, `PROTOCOL-registry.md`, ADR-2122 and `env-classes.json` moved between the old stamps and the pin.

## Findings

**F1. The licensing rule's CI claim is not what the gate does (AB-33.8, Tension).**
- Trigger: `docs/developer/licensing.md:66-71` says no permissive crate may depend on a sidestr crate, that a linking component declares AGPL, and that `scripts/ci/check-crate-licensing.sh` enforces this on every push.
- Consequence: the gate iterates `services/*/Cargo.toml` (`scripts/ci/check-crate-licensing.sh:61`) and checks only that each crate's declared licence matches the texts and README beside it (`:15-23`). A `services/` crate declaring `MIT OR Apache-2.0` that took a `sidestr-*` dependency would pass. ADR-2112's "crates.io only, never by git" (`docs/adr/ADR-2112-sidestr-crates-live-in-sidestr-rs.md:39-41`) is not enforced either: `lib/sidestr-agent.nix:29-36` fetches sidestr-rs from GitHub at a pinned rev, and CI passes.
- Close: add a dependency check (for example `cargo metadata` over `services/*`, refusing `sidestr-*` under a permissive licence), or reword licensing.md to say what the gate checks.
- The topic's old R2-R5 citations (`licensing.md:46-54`) pointed at the dream-engine paragraph. They now point at `:64`, `:66-68` and `:70-71`.

**F2. The kind-38420 binding is built, but documents call it unbuilt (AB-34, Drift).**
- Evidence: `management-api/lib/sidestr-spend-key.js:33` defines `BINDING_KIND = 38420`, and `:94-110` builds and signs it with `k_id`. `management-api/routes/chain-payments.js:39` consumes it, and `docs/PROTOCOL-registry.md:174` records it as built.
- Conflict: `config/sidechain/README.md:190-194` still lists it under "Not yet built", and so did AB-34's prose and AB-34.5's S5 node.
- Fix applied: the topic now marks S5 as Drift.
- Close: update the README's not-built list.

**F3. A devuser directory inside the role-only secrets mount (AB-36.3).**
- Evidence: in both modes, `_ab_pg_credential_prepare` creates `/run/secrets/ruvector-pg/` owned by devuser at 0700, with the RuVector password at 0600 (`config/entrypoint-unified.sh:473-475`, `:486-488`, called at `:507`). This is outside the role plan.
- ADR-2122 records this and says the rehearsal was not re-run with the directory present (`ADR-2122-...-identity-port.md:772`).
- Limit: from source, nothing here breaks a role boundary, because role directories stay sealed 0500 (`config/lib/role-custody.sh:351-353`). Still, the panel's "one sealed directory per role" picture was incomplete. It now carries the node and an Open.
- Close: run a flag-on rehearsal with the directory present, and decide whether check (a) should allow-list it.
