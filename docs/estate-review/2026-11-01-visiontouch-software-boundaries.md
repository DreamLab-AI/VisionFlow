# Visiontouch software boundaries, evidence and decision review

Native transport and software-guard tests provide substantial offline coverage, but the Studio can report output off after an unconfirmed shutdown and discard the attempt that led to a disconnect. The previous diagrams overstated several guarantees: evidence writes are not protected by a device-bound type, continuous-force policy is not enforced by the SDK alone, and the proposed SpacePilot-to-graph event connection does not exist in the cited controller. This pass corrects those claims and records the remaining work without changing device code or force limits.

Scope: all six local decisions, their Context, Decision, Consequences and Verification sections, the governing baseline, and all 39 panels in VT-01 through VT-08. The ADR preamble and template are process documents, not two additional implemented decisions. The generated index was checked by the quality gate. The cross-repository ADR-2017 is reviewed where it governs this integration. This is a bounded source and software assessment, not a proof of every protocol fact, every historical provenance ordering, physical safety, paper eligibility or legal compliance. The wider estate audit remains in progress.

## Findings and acceptance work

| ID / priority | Verified observation | User consequence and proposed acceptance |
|---|---|---|
| VT-A1 / high | `worker.rs:433-451` ignores shutdown errors in `disconnect`, drops the hardware and reports output off. `fault` reuses that path and also says output off. A `Hardware` wrapper returning a shutdown error while still armed reproduces the message. | The operator cannot distinguish a successful neutral transaction from an unconfirmed shutdown. Preserve the shutdown result and show the latter explicitly. Test direct disconnect, read failure, write failure and failed normal finish; none should assert confirmed physical release. Even a successful transport shutdown is not a force measurement. |
| VT-A2 / high | `disconnect` clears `running` and resets the controller without finalising its rows (`worker.rs:433-439`). An active simulated liveness attempt with ten additional samples disappears without an evidence directory. Fault, Quit and reconnect can use this path. | The most useful failure trace can be missing. Retain an aborted attempt and the shutdown outcome through these paths, while preserving the existing order of shutdown attempt before persistence. Test the last sample, stop reason, session reference and incomplete shutdown state after reopening the evidence. Do not award a pass from an interrupted attempt. |
| VT-A3 / medium | `evidence.rs:24-34` constructs `OutputOff` from any supplied false Boolean; writers borrow the reusable token. A token created before simulator arming still permits directory creation afterwards. The normal `finish` path does attempt shutdown first. | The type is an assertion of caller intent, not an enforced device-state lifetime. Document that distinction or bind persistence authority to the disarmed state. Test stale-token reuse as well as `confirm(true)` rejection; do not infer a live motor write from this API-only probe. |
| VT-A4 / medium | `evidence.rs:534-544` runs `git rev-parse HEAD` in the current working directory. The archived visiontouch test binary, launched from VisionFlow, reports the VisionFlow commit `45781a5…`. | Evidence can identify unrelated sources. Record build-time source identity, dirty/build provenance and runtime configuration separately. Moving the same executable between unrelated directories must not change its build identity. |
| VT-A5 / medium | `registration.rs:187-190` accepts a return within 2 mm when pairwise spread is absent. One return mark at the origin passes `return_ok`. The mark is still gated on stillness. | A successful gate need not establish repeated returns to the physical reference. Decide the minimum repetitions and require independent move-away/return trials; test a single mark, repeated unchanged marks and genuinely separated trials. Pose reproduction remains an operator procedure. |
| VT-A6 / medium | `pointer.rs:225-233` drains an unbounded channel with `try_iter`; Studio `worker.rs:1292-1306` also drains commands before its tick. Neither drain has a count/time budget. `Device::sample` services the old demand before the new sample reaches application interlocks (`lib.rs:529-537`). | “Cannot starve sampling” and “stops at once” were stronger than the implementation. Bound/coalesce pending work and specify the ordering and latency that can be tested. No sustained-producer starvation or real-device latency was measured in this pass. |
| VT-A7 / qualification | A valid SDK guard configured to 2 N / 300 counts sustains a 2 N model command for 12 simulated seconds, at offsets `[0, 0, -268]`, while serviced every 2 ms. A subsequent 26 ms gap yields zero. | Defaults can be raised up to ceilings while disarmed. The SDK enforces magnitude, slew, freshness and DAC bounds; Studio implements its own continuous/dwell policy. This is not a demonstrated violation by Mass Lab or Studio. Any future caller must explicitly implement the missing application policy. |
| VT-A8 / model/documentation | At fixed inward velocity, doubling stiffness changes cube force from 0.19 to 0.34 N, plane from 0.19 to 0.34 N and balloon from 0.204 to 0.388 N: damping does not scale. Springs have identical body positions at 150 and 300 N/m but doubled returned pen force (`effects/lib.rs:336-343`). Finite extreme Water velocity produces infinity/NaN. | Total force is not always proportional to stiffness, and scaled pen reaction is not equal to body contact. Keep the model qualification visible. The SDK rejects non-finite demands; the extreme-input probe does not establish an unsafe actuator output. Test useful operating ranges and passivity/energy behaviour before claiming realistic contact. |
| VT-A9 / integration drift | `SpacePilotController.ts:458-479` mutates object position and quaternion directly. The inspected file has no call into `useGraphEventHandlers`; those pointer handlers separately emit the drag messages. | The intended pose adapter needs a real interaction contract, not an assumed existing edge. Verify select, drag, release, disconnect and stale-input cancellation through the server-authoritative path before calling it integrated. Orientation remains uncalibrated and no bridge crate is present. |
| VT-A10 / verification gap | The full gate omits `tools/port-recorder/tests/check.py`. This separate test failed on snapshots with EPERM in the audit container. | A green gate cannot qualify the C/assembly preload path. Add an explicit supported-environment check or an explicit unsupported result; do not silently accept captures with incomplete snapshots. Review whether snapshot failure is also surfaced prominently enough in operator tooling. |

Two additional source qualifications remain. `with-port-access:10-17` takes its direct-exec branch before checking EUID, so the documented prohibition on root execution is a policy, not a universal script guard; no root/device execution was attempted. Evidence CSV and JSON writes use direct `fs::write` (`evidence.rs:489-519`), so process interruption can leave a partial pair or truncated rewrite. Atomic replacement and recovery validation are proposed work, not tested crash-recovery guarantees.

Wayland hold handling retains a documented problem: a lost focus event can leave Space held while the UI still increments its heartbeat (`main.rs:323-330`). The 250 ms stale-heartbeat rule cannot detect that specific continuing-heartbeat case. The revised diagram no longer promises that focus loss always stops an attempt.

## Comparison and useful next steps

Visiontouch's current contribution is a reproducible study of one owned legacy unit, with Rust software models and provenance discipline. Its constraints differ from supported haptic frameworks and modern device services; the evidence does not support positioning it as an interchangeable hardware driver or a calibrated force product.

| Primary reference, consulted 1 November | Relevant comparison and inference |
|---|---|
| [CHAI3D device abstraction](https://www.chai3d.org/download/doc/html/chapter6-haptic-devices.html) | Documents device discovery, position/orientation/buttons and force APIs, custom-device adapters, coordinate conventions and a desired communication period below 1 ms. Visiontouch's Studio targets 2.4 ms and has a reset-relative coordinate frame. Inference: an adapter needs explicit axis, units, timing and capability declarations; sharing API names would not establish equivalent stability or performance. This is not a recommendation to increase the existing device's loop rate. |
| [Haply Inverse SDK](https://docs.haply.co/inverseSDK/) | Documents a local WebSocket/HTTP service for discovery, communication, monitoring and streaming. Inference: a future input-only lab bridge benefits from explicit device/session identity, timestamps and connection state. This is an architectural comparison, not a claim that Haply supports this arm or that its safety behaviour transfers to it. |
| [Force Dimension SDK manual, watchdog API](https://downloads.forcedimension.com/sdk/doc/fdsdk-3.14.0/user%20manual%20-%20Haptic%20SDK.pdf) | The documented watchdog on compatible devices disables forces in firmware after missing commands. Visiontouch's freshness test runs only when its worker runs. Inference: these are different failure boundaries; software timeout tests cannot establish autonomous shutdown during a host stall. No firmware-watchdog capability is inferred for the owned arm. |

Prioritise trustworthy trial reporting: preserve failed attempts, distinguish commanded zero from confirmed transport shutdown, and identify the executable independently of its working directory. Those changes improve the owner's ability to diagnose the next attended session without raising any force envelope.

For a later input-only VisionClaw experiment, propose a predeclared comparison against mouse or controller input: selection errors, drag completion time, unintended selection after reconnect, stale-stream cancellation and repeated registration offset. Start with recorded/simulated pose streams through the real client event path. A force-return path is outside the current decision. Success means a measurable improvement for a named graph task, not merely a moving cursor or a working socket.

Repository legal policy is an audit input, not a conclusion of this review. Attempts to retrieve the official [section 50BA](https://www.legislation.gov.uk/ukpga/1988/48/section/50BA) and [section 50B](https://www.legislation.gov.uk/ukpga/1988/48/section/50B) pages were rejected by the web reader's content-type handler. No legal validity, current rights-holder status or publication clearance is certified here.
