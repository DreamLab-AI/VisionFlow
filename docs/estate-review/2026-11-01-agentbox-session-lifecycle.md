# Agentbox session lifecycle, work protection and delivery

Agentbox uses its native `agentbox-sessions` service. Agent of Empires is retired; remaining `aoe-` directory names do not make it an active dependency. This review assesses all sections of ADR-2153 against agentbox `9dfc27b16e82e9786535a55e790710493dd51fdf`, corrects AB-12.15 and adds AB-39. It does not certify the rest of agentbox or the superseded ADRs.

Seven added private-tmux tests expose work-protection, blocked-input, delivery-reporting and lifecycle gaps. The final native suite passes 66 tests, including those probes. Nine existing Node tests pass; the provider-launch tier is deliberately skipped. These passing probes reproduce current defects, not fixes. [Evidence and reproduction](evidence/2026-11-01/ab-sessions/README.md) retain exact source exports, the test patch, logs, a counterexample and a bounded live observation.

## Evidence boundaries

Rust tests ran against an immutable source archive with synthetic Git repositories, dummy shell processes and private tmux servers. Boundary HTTP was disabled in those fixtures, provider variables were removed, and no operator session was sent input or switched. Node checks used the pinned primary checkout read-only, mock sockets and a local bridge with an absent tmux target; they did not launch real agents. Installed and source JavaScript session clients have identical hashes.

At 09:48 UTC on 1 November, a read-only supervisor/socket observation found the daemon running and eight entries: seven seeds plus the external coordinator. Antigravity reported a sign-in blocker; the others reported idle. This does not establish provider round trips, successful boundary events or the running binary's source identity. ADR cold-boot and activation receipts remain historical evidence, not freshly reproduced results.

Separately authorised cleanup removed the retired `~/workspace/agentbox-of-empires` checkout. It was clean including ignored files, had one worktree, had no local-only commits, matched fresh remote `main` at `33e806ad`, and had no process references. Removal was verified and the receipt retained. The native service's active `aoe-*` worktrees and retained recovery volume were left intact. This cleanup does not close ADR-2153's mount-migration obligation.

## Findings and acceptance criteria

**S1 — Restart protection checks the desired directory and treats inspection errors as clean.** `plane.rs:321–325` supplies `dirty(plan.dir).unwrap_or(0)` to the planner; `reconcile.rs:82` checks it only when the desired seed has `worktree=true`. Switching a seed to the shared directory therefore bypasses dirty work in its old worktree. A second probe breaks the synthetic worktree's `.git` pointer while its registered directory remains present: a status error becomes zero changes and recreation proceeds. Both replace the process while preserving the old files. They contradict the promised hold, not a no-file-deletion claim. A counterexample matters: merely changing the worktree prefix causes Git's existing-branch guard to fail before the old session is killed. Check the observed old directory as well as the destination, refuse unknown status, and define treatment of nested submodule work. Acceptance must cover directory changes, worktree-to-shared changes, unreadable/corrupt Git metadata and submodule edits without killing the protected process.

**S2 — A session can be listed as blocked and still accept input.** For non-seed owned sessions, `status` reconstructs tool-specific blockers (`plane.rs:373–383`). `send` looks up only manifest seeds (`:405`) and otherwise classifies with common blockers. A dummy API-created tool prints its configured login blocker: status reports blocked, but send succeeds and the dummy process consumes the text. This is inconsistent guard behaviour for an authorised caller, not a socket ACL bypass. Persist the resolved launch contract and use one classifier for listing and sending. Verify no text reaches seed, API or coordinator sign-in/trust prompts; specify the coordinator's deliberate exceptions.

**S3 — Input can be delivered before the caller receives failure.** `plane.rs:411` submits text before writing the busy hook at `:415`. Making the synthetic hook directory a file causes the API to return `ok:false` after the dummy process consumes the line. The bridge catches any session-send error and types again through legacy tmux (`server.mjs:157–168`). Consequently a post-send failure can produce duplicate input; a 12-second JavaScript timeout also leaves completion unknown. The probe proves delivery followed by error, not a live duplicate through the bridge. Boundary HTTP failure is separately logged fail-open and is not the error propagated in this probe. Introduce a request ID, delivery-stage receipt and deduplication; fall back only when non-submission is established. Test post-submit status failure, lost reply, timeout while waiting for the operation lock and retry after reconnect.

**S4 — Declaration removal and controller lifetime do not fully converge.** `Plane::load` reads manifest/contract once (`plane.rs:183–187`); reconciliation visits only its stored seeds. The probe removes a seed: the existing object still sees it. A freshly loaded object sees no desired seed, but leaves the surviving owned session present, and `close` refuses because its origin is `seed`, not `api`. The managed rebuild apply class explains how configuration normally reloads; it does not supply removal semantics when tmux survives a daemon restart. CLI `reconcile`, `send`, `create` and `close` also construct independent controllers (`main.rs:96–122`), with separate locks and restart maps. Route mutations through one controller or establish cross-process ownership, persist restart accounting where required, and specify stop/archive/hold behaviour for removed seeds. Acceptance must include daemon-only restart, two controller processes, removal with dirty work and repeated manual reconciliation.

**S5 — API worktree intent is lost from reporting and close.** An API request with `worktree=true` creates a registered worktree, but its status row hardcodes `worktree:false` (`plane.rs:383`). Close kills the session and leaves that worktree and branch; the legacy reaper targets a different old root. The probe verifies both. Close also rebuilds a plan with `worktree:false` (`:475`), so its boundary project path can name the shared directory instead of the API session's actual directory; that path discrepancy is source evidence, not a captured HTTP event. Store launch/worktree identity durably. Expose a deliberate archive/cleanup operation with dirty, unmerged and non-regenerable ignored-file checks. Never infer that closing a pane authorises deleting work. Test status, boundary identity and repeated close/cleanup for API worktrees.

**S6 — The picker cannot prove it selected the invoking client.** `pick.rs:16–26` filters clients by the session named through `TMUX_PANE`, then selects the highest activity timestamp. Its existing unit test explicitly chooses the more active of two clients in that session. Passing the chosen TTY with `-c` is better specified than omitting a target, but it does not establish the ADR's own-client invariant. No operator client was attached or switched in this audit. Resolve a trusted invoking client identity or refuse ambiguity. Validate with two private attached clients and with a process that merely inherits tmux variables, proving the other client never moves.

**S7 — Idle and boundary submission are weaker than successful agent work.** `status.rs:68–71` returns idle after the settle interval even without a ready pattern or completion hook. Hook files have no generation or expiry; coordinator status is separately derived from target presence and busy state. Boundary create failures retry for seed/external sessions, while failed turn/close events only log. Direct CLI `mark` writes a hook without the `Plane::mark` boundary path. These are source-visible lifecycle limits, not proof that every observed idle row is wrong. Expose readiness, response completion and binding delivery separately; retain durable pending boundary events when their loss matters. Acceptance should cover silent-but-alive tools, late hooks from an earlier session, lost hooks, provider 401s and management outage/recovery. Do not use an idle label as the acceptance gate in decision 11.

## Comparison and utility

[Agent of Empires' current upstream documentation](https://raw.githubusercontent.com/agent-of-empires/agent-of-empires/main/docs/index.md), checked on 1 November, describes a Rust/tmux manager with terminal and browser views, per-agent status, worktree lifecycle and optional container isolation. That is an external comparator, not an installed component or a recommendation to restore the removed fork. Agentbox's useful distinction is its declared estate roster and integration with identity, voice and Nostr workflows. Those integrations justify ownership only when users can trust restart protection, delivery receipts and the handover between surfaces; a smaller codebase alone does not establish that benefit.

The [tmux manual](https://raw.githubusercontent.com/tmux/tmux/master/tmux.1) permits multiple clients on a session and separate private servers. That makes invoking-client identity and private test isolation real design concerns, rather than unusual edge cases. The present fixture isolation is a useful testing pattern; the picker still needs the narrower identity guarantee in S6.

Prioritise three user outcomes: preserve an agent's working context during configuration changes; report whether a command was submitted without unsafe retry; and give a closed session a discoverable worktree/receipt disposition. Measure duplicate submissions, protected-process replacement, orphaned API worktrees and successful provider round trips across a restart. Keep daemon liveness, tool readiness and identity delivery as separate visible states. Broader market positioning and the rest of agentbox remain part of the open estate audit.
