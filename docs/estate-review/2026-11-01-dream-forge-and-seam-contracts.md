# Dream-engine forge and seam contract audit

Optional automerge can leave a pull request ready for review when merge enablement fails. Publication also lacks an expected commit hash, and self-reference detection recognises only a known repository name, protected-path configuration and three fixed crate locations. These are gaps in the optional library path; the inspected agentbox adapter calls draft publication directly, so its automerge option remains inert.

This pass assesses ADR-DE-005 and ADR-DE-006 section by section, corrects AB-23.6 and adds three DE-04 panels. It extends the [candidate review](2026-11-01-dream-candidate-and-evidence.md) and [recovery review](2026-11-01-dream-recovery-and-source-supply.md). Seven of the nine local engine decisions now have dated section assessments; DE-001 host parity and DE-002 provenance/dependencies remain. Nineteen other AB-23 panels and the nested engine diagram corpus remain queued. Owner decision statuses and production implementations are unchanged.

## Evidence and limits

Dream-engine is pinned to `815f963b1cbd6999e78144ce5475005ae1dd1d8e`; agentbox to `9dfc27b16e82e9786535a55e790710493dd51fdf`. [Input hashes](evidence/2026-11-01/dream-forge-source-manifest.json) bind the reviewed files and compare selected adapter inputs with their retained diagram revisions. A source match establishes identity, not semantic correctness.

[Thirteen audit tests pass](evidence/2026-11-01/dream-forge-seam-probes.log). They exercise the real `GhForge`, publication policy and local runner through [committed integration tests](evidence/2026-11-01/dream-forge-seam-probes.rs), with real Git pushes to local bare fixture repositories and a [Rust replacement for the gh executable](evidence/2026-11-01/dream-forge-fake-gh.rs). That executable records arguments and controlled responses; it never contacts GitHub. Existing [seam tests](evidence/2026-11-01/dream-forge-existing-seams.log) pass 7, [automerge tests](evidence/2026-11-01/dream-forge-existing-automerge.log) 13, [persistence tests](evidence/2026-11-01/dream-forge-existing-persist.log) 22 and [runner tests](evidence/2026-11-01/dream-forge-existing-runner.log) 6: **61 executed tests pass**. Passing defect assertions reproduces a shortcoming; it does not repair it. The earlier 555-test workspace baseline was not rerun here.

No live forge, model, notification service, memory store or whole-night adapter run was exercised by these probes. Command sequencing and local pushes are observed; remote GitHub state, a concurrent head replacement and actual merging are not. Adapter findings below are source assessments. [Reproduction notes](evidence/2026-11-01/dream-forge-reproduction.md) explain the offline fixtures, serial environment handling and retained initial compilation error.

## Findings and acceptance work

Paths without an agentbox prefix are relative to dream-engine.

| Finding | Evidence and user consequence | Acceptance required |
|---|---|---|
| DE-F1 / medium: enable failure can leave a ready PR | `seams.rs:469-487` runs ready before merge. The command fixture accepts ready and rejects merge; publication returns Allowed, enabled=false and an error, with no undo command. `persist.rs:278` nevertheless promises that the PR stays a draft. Its existing refusal test checks returned fields, not remote draft state. | Represent partial readiness explicitly and reconcile remote state after an ambiguous failure. Restore draft status only when the observed state and policy permit it; blindly undoing after an uncertain merge result is insufficient. Test real GitHub behaviour before activation. |
| DE-F2 / high if optional merging is enabled: evaluated identity is not bound to the merge | `DraftPr` at `seams.rs:341` names a checkout, slug and branch but no expected SHA. The merge invocation at `481` has no expected-head guard. The fixture records no head query or outcome query; it verifies the local bare remote received the branch tip, not that a changing remote PR head could never be merged. | Carry the evaluated commit through publication, compare origin/target/PR identity, and require that commit when requesting merge. Record the returned PR head and eventual merge outcome. Add a concurrent-head-change case. This is an unclosed integrity boundary, not a demonstrated live unauthorised merge. |
| DE-F3 / medium: self-reference protection is a location heuristic | `automerge.rs:44-51,110-118,144-149` checks a canonical repository slug, protected-path policy and three fixed Cargo.toml locations. A tracked fixture containing the actual package name dream-gate under components/dream-gate is not detected and receives Allowed. The canonical engine slug still refuses enablement. | Define self-reference by the trusted package/dependency graph and protected components, including renamed forks and relocated crates. Test those cases before interpreting “contains the gate crates” literally. The source does not support the broader guarantee. |
| DE-F4 / medium: publication success is weaker than a usable PR receipt | `seams.rs:512-533` turns any successful create stdout into Some(trimmed text), including an empty string. `persist.rs:299` treats pushed plus Some as clean. The empty-output fixture proceeds to queries with an empty URL. A failed create leaves the pushed branch and loses its stderr in PrOutcome; a failed push suppresses gh altogether. | Validate a nonempty, correctly identified PR response and retain structured push/create errors. Expose partial publication so operators can recover the existing branch. Empty stdout is a deliberately malformed successful CLI response, not a claim about normal gh output. |
| DE-F5 / API qualification: rejection prevents merge, not draft publication | `persist.rs:298` publishes before the policy decision at `322`. Tests confirm that a Reject verdict and a self-referential slug still push and create a draft before merge refusal. | State publication eligibility as a caller precondition, or enforce it in the helper. Agentbox guards its direct forge call with acceptance at `engine.rs:1733-1774`; this API observation does not establish a host gate bypass. |
| DE-F6 / medium: asynchronous and failure contracts are overstated | `seams.rs:96,148,320,367` and `runner.rs:30` expose three future-returning interfaces and two synchronous ones. Forge publication returns a partial outcome, not Result; MemorySink explicitly permits best-effort handling. A JsonlSink write error is returned without writing run state. Unit return from Notifier cannot guarantee timely completion or absence of panic. GhForge subprocess calls have no explicit deadline in these implementations. | Correct ADR-DE-005's all-other-traits-async and automatic-error-reporting claims. Define host-owned deadlines, cancellation, partial outcomes and journalling per seam. The missing publication deadline is source-observed; no hanging real forge was induced. |
| DE-F7 / low: raw timeout metadata disagrees with classification | `runner.rs:69` always sets timed_out=false. A real sleep command limited to one second exits 124 with that flag false; `receipts.rs:231-249` correctly classifies it as TimedOut from the exit code. | Make the raw field consistent or document that consumers must classify the outcome. This probe demonstrates contradictory metadata, not false acceptance. |
| AB-F1 / qualification: delivery and accounting outcomes diverge | Agentbox `engine.rs:1710` journals Persisted before publication, then calls publish_draft at `1774`. Common ledger handling at `1857` also follows local acceptance, rejection and no-verdict branches. `records.rs:55-80` makes append failure fatal but logs commit failure and continues. Memory recording at `engine.rs:1889-1903` records failure and continues. | Preserve separate evaluated, persisted, pushed, draft-created, ledger-appended, ledger-committed and memory-recorded outcomes. Test each failure boundary in the host. A completed night or Accepted notice alone cannot prove all of them. Existing earlier inbox/request effects remain outside the persist-before-publication boundary. |

Required-check lookup uses the classic branch-protection endpoint and asks for at least one named check. The fixture verifies refusal for a wrong base, an empty list and API failure. It does not establish coverage of every GitHub ruleset or protection configuration. GitHub remains responsible for enforcing its merge requirements; no bypass of those requirements was demonstrated.

## ADR-DE-005 section dispositions

| Section or clause | Assessment |
|---|---|
| Context: replace product-specific dependencies | Five public interfaces exist. Hosts select implementations and orchestration; this is a toolkit contract, not proof that every host path uses every seam. Agentbox constructs its memory sink directly in the inspected path. |
| Decision table: Llm and model identity | Implemented by complete and identity; the result and identity interfaces are present. Provider availability and model quality are outside this pass. |
| Decision table: memory and evaluation | MemorySink returns a fallible future; EvaluatorRunner returns a synchronous ExecOutcome. Local and scripted runners exist. Error propagation and storage are caller policy. |
| Decision table: notification and forge | Notice variants and draft/query/enable methods exist. Forge's lower-level methods can be called directly; policy is enforced by persist::publish, not by every Forge call. |
| Decision: synchronous evaluator, all other traits boxed futures | Incorrect for Forge, which is synchronous. Llm, MemorySink and Notifier use boxed futures and remain dyn-compatible. |
| Decision: notifier infallible, must never stop a run | Unit return is implemented. Fail-open logging is an implementation obligation, not a type-level guarantee against panic, blocking or cancellation. |
| Consequences: product code in consumer and versioned public contracts | Consistent with the inspected separation. Versioning discipline across every downstream consumer was not assessed here. |
| Consequences: other four fallible, errors recorded rather than swallowed | Overstated. Forge collapses push/create failures into fields; MemorySink is best effort and has no journal dependency. Agentbox has its own error recording. DE-F6 distinguishes these contracts. |
| Consequences: built-in implementations and module locations | NullSink, JsonlSink, StderrNotifier, GhForge, LocalRunner and ScriptedRunner are present at the named module boundaries. Existing seam and runner tests pass. |
| Deliberate boundary: event notices versus night-level publication | Notice carries NightSummary, LostPr, HarnessStuck and Accepted; host-level relay/digest delivery is separate. No new whole-night delivery guarantee follows. |
| Deliberate boundary: optional typed MemoryRecord fields | deep, night_date, witness and source are optional; existing compatibility tests pass. This is serialisation compatibility, not evidence that the deployed store records every outcome. |
| Deliberate boundary: typed AttemptError | PatchDidNotApply, Provisioning and Prepare variants are present in candidate.rs. Broader candidate safety remains governed by the preceding candidate assessment. |

## ADR-DE-006 section dispositions

| Section or clause | Assessment |
|---|---|
| Context: evaluator acceptance does not mean a wanted change | Sound distinction. Neither this audit nor engine acceptance measures maintainer demand or correctness beyond chosen evaluators. |
| Decision: human default, autoMerge and automerge alias | Default false and alias are implemented in config.rs:437-443. The disabled fixture creates a draft and performs no policy queries or ready/merge commands. |

## Diagram dispositions and utility comparison

AB-23.6 now shows the common ledger tail, local acceptance and rejection branches, fatal append versus logged commit failure, best-effort memory and final notices. Its changed inputs match the retained source pins. DE-04 maps the five interface contracts, optional merge sequence and identity limitations. [Focused gates](evidence/2026-11-01/dream-forge-diagram-gate.log) and the [adapter gate](evidence/2026-11-01/dream-forge-adapter-gate.log) pass; all four changed/new panels were visually inspected. Rendering the remaining AB-23 panels does not close their semantic review.

Nested NIT-03 and CRT-02 were read in full for comparison. NIT-03's claim that enable failure leaves an ordinary draft is contradicted by DE-F1, and its self-reference language needs DE-F3's qualification. CRT-02's default local-use narrative should distinguish interface substitutes from a configured host with a model and real publication; notifier infallibility also needs the signature-versus-runtime qualification. These are owner findings, not edits or completion claims for that nested corpus.

[GitHub CLI's merge reference](https://cli.github.com/manual/gh_pr_merge) provides a match-head-commit option. Using it with the evaluated SHA would close one part of DE-F2; it would still need correctly bound publication and outcome recording. [The ready command](https://cli.github.com/manual/gh_pr_ready) supports undoing readiness, which makes compensating behaviour possible but does not remove the need to inspect ambiguous remote outcomes. These are design inferences from documented commands, not features already implemented here.

[Renovate's automerge guidance](https://docs.renovatebot.com/key-concepts/automerge/) describes selected dependency updates merged after required tests, with branch freshness and per-target sequencing constraints. Dream-engine addresses a broader kind of candidate change with repository-chosen evaluators. Its useful distinction would be evidence that maintainers receive wanted, reproducible changes with low review cost; generic unattended merging alone does not establish that advantage. Compare at equal repository workloads: verified-head draft delivery, reviewer acceptance, reviewer minutes, rollback rate and visibility of partial failures. No comparative benchmark was run.
