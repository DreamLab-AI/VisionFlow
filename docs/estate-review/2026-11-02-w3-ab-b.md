# Agentbox management API, adapter spine and compose overlays

I assessed all 46 panels of three agentbox topics: AB-03 (management API request lifecycle, 17 panels), AB-04 (adapter spine, 15 panels) and AB-06 (compose overlays and sidecars, 14 panels). The evidence is source tracing at agentbox `c57d9c0508f4`. Outcome: 7 panels accurate, 38 corrected, 1 accurate within stated limits, and none left inaccurate. All three topics were stamped at `6500582`, 120 commits behind the pin, so each was restamped and every citation re-resolved by symbol. Many citations were already wrong at the old stamp, because the generator checks only that a cited line exists, not what the line says. The three most important findings are that AB-04.9 drew the in-process `embedded-ruvector` adapter writing 384-dimension embeddings to Postgres when the shipped `external-pg` adapter is the Postgres writer and stores no embedding at all; that the `agentbox_adapter_health` gauge, which the baseline names as the stage-4 SLO surface, is never set; and that the stage-1 schema rejects the `[adapters] connect_timeout_ms` override the lifecycle reads.

## Findings

**W3B-01: the memory panel drew the wrong adapter, and the Postgres writer stores no vector.**
- **Trigger:** AB-04.9 showed `EmbeddedRuvectorMemoryAdapter` upserting into `memory_entries` with a 384-dimension embedding.
- **Evidence:** the embedded adapter is an in-process `Map` with 64-dimension term-frequency vectors (`management-api/adapters/memory/embedded-ruvector.js:4-9`, `:31-47`, `:59`). The manifest selects `external-pg` (`agentbox.toml:20`). Its `store` runs `INSERT ... ON CONFLICT` over `id, namespace, key, value, source_type, metadata`, with no embedding column (`management-api/adapters/memory/external-pg.js:89-96`).
- **Consequence:** agentbox's own `/v1/memory/search` is an `ILIKE` text match (`management-api/adapters/memory/external-pg.js:103-115`) and is unaffected. If no database-side trigger embeds these rows, estate-side semantic search over the shared table (HNSW) cannot reach agentbox-written memory. Source cannot settle that.
- **Close by:** confirming or ruling out an embedding trigger on `memory_entries`, or having the adapter embed client-side.
- **Topic change:** the panel is redrawn, with a **Drift** and an **Open** marker.

**W3B-02: the adapter-health gauge is never set, and the topic had its encoding wrong.**
- **Evidence:** `agentbox_adapter_health` is declared (`management-api/observability/metrics.js:35-40`). Its setter `setAdapterHealth` (`:202-204`) has no caller anywhere in the repository; only a test checks that the metric name exists. The help text and the setter agree on 0 unhealthy, 1 healthy, 2 degraded. AB-04.8, AB-04.15 and AB-04.16 gave healthy as 2.
- **Doc drift:** BASELINE stage 4 says the SLO is "surfaced as the `agentbox_adapter_health` gauge" (`docs/BASELINE-container.md:119`).
- **Consequence:** `/metrics` never reports slot health, so any alert on this gauge is silent.
- **Close by:** calling the setter from the `toLegacyHealth` result at boot (`management-api/server.js:1380`), or striking the gauge from BASELINE.
- **Topic change:** AB-04.8, AB-04.15 and AB-04.16 are corrected, with a **Drift** marker.

**W3B-03: stage 1 rejects the knob that stage 2 reads.**
- **Evidence:** `connectTimeoutFor` reads `[adapters] connect_timeout_ms`, as a scalar or a per-slot map (`management-api/adapters/lifecycle.js:107-109`, `:119-127`). The schema's `[adapters]` object sets `additionalProperties: false` and does not declare that key (`schema/agentbox.toml.schema.json:50-52`). The validator compiles the schema with Ajv (`scripts/agentbox-config-validate.js:125-128`) and exits 1 on any error (`:1920`).
- **Consequence:** an operator who follows BASELINE or the lifecycle header and sets a per-slot deadline fails validation.
- **Close by:** declaring the key in the schema.
- **Topic change:** **Tension** marker on AB-04.15.

**W3B-04: the NIP-98 header may not re-verify behind the `/mgmt/` strip.**
- **Evidence:** the proxy's `/mgmt/` route strips its prefix (`config/nip98-proxy/proxy.mjs:304-310`) and forwards the caller's NIP-98 header verbatim (`:886-892`). The API rebuilds the URL from the stripped path (`management-api/middleware/auth.js:73`). `verifyNip98` accepts only an exact or suffix match against the signed `u` tag (`mcp/servers/nostr-bridge.js:545-546`).
- **Consequence:** a client that signs the `/mgmt/...` URL it actually calls could get 401 at the API. Only a runtime request through `:9096/mgmt/` can settle this.
- **Topic change:** AB-03.15 previously had the API receiving `/mgmt/v1/mandate`, which was wrong; it is corrected, with an **Open** marker.

**W3B-05: a mandate write does not reach the hash chain.**
- **Evidence:** AB-03.15 ended the mandate create in an events-adapter dispatch hashed into the JSONL log. `createSignedMandate` signs a kind-30078, or warns and keeps the mandate unsigned, then saves a local registry entry and replies 201 (`management-api/routes/mandate.js:191-231`, `:377`). It emits nothing to the events slot.
- **Consequence:** mandate grants are absent from `/v1/system/audit-chain`, so the tamper-evident log cannot show who was delegated what.
- **Close by:** dispatching a `mandate.created` event through the events slot, or stating in ADR-043 D4.5 that the registry, not the chain, is the record.
- **Topic change:** corrected, with a **Drift** marker.

**W3B-06: "operator-gated" routes are only authenticated.**
- **Evidence:** `POST /v1/exec/record` is described as operator-gated (`management-api/server.js:433`, `routes/exec-record.js:6-7`), but attaches no `requireOperator`. Any NIP-98-verified signer passes the global hook in hybrid or NIP-98 mode (`middleware/auth.js:194-199`). `/dream/status` uses the same wording (`routes/dream.js:6`).
- **Consequence:** any authenticated principal can append journal events.
- **Close by:** adding `authz.requireOperator`, as `routes/mandate.js:311` does, or rewording the comment.
- **Topic change:** **Tension** marker on AB-03.1.

**W3B-07: the events slot's write path is never redacted.**
- **Evidence:** the privacy layer gates by method name (`middleware/privacy-filter.js:283-313`). `dispatch`, `claim`, `close`, `del` and `spawnAgent` are not classed as mutations. `LocalJsonlEventsAdapter.dispatch` therefore passes through to the hash-chained log unredacted, whatever the slot policy. The ADR-2005 rationale block (`middleware/privacy-filter.js:236-280`) explains the name rule but does not name `dispatch` as a deliberate exclusion.
- **Consequence:** personal data carried in an event payload reaches the durable, append-only log, where it cannot be corrected without breaking the chain.
- **Close by:** adding `dispatch` (and the beads `claim` and `close` writes) to the mutation set, or recording the exclusion as a decision.
- **Topic change:** **Tension** marker on AB-04.5.

**W3B-08: `agentbox.sh health` signals failure on one path only.**
- **Evidence:** `--json` exits 0 regardless (`agentbox.sh:1148-1151`). Without `jq`, the command prints the payload and returns 0 (`:1220-1223`).
- **Consequence:** a script that pipes `agentbox.sh health --json`, or runs on a host without `jq`, never sees a degraded slot as a failure.
- **Close by:** exiting non-zero on `--json` when `degraded_count > 0`, and failing rather than passing when `jq` is absent; or documenting both paths as non-gating.
- **Topic change:** AB-04.16 now draws both branches, with a **Tension** marker.

**W3B-09: AB-03.16 had the payment middleware consumers wrong.**

- **Consequence:** a reader of the old panel would treat both middleware files as dead code and could delete the rail's spend cap.
- **Close by:** done in the topic; no product change needed.
- **Topic change:** corrected, with a **Drift** marker.

**W3B-10: the route census is incomplete, and auth has a third credential.**

- **Close by:** adding a route-table panel for status, chain, chain-payments and briefing.
- **Topic change:** AB-03.3, AB-03.4, AB-03.9 and AB-03.13 are corrected. AB-03.2 carries a **Drift** marker for the missing surfaces.
