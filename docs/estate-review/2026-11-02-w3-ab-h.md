# Agentbox service crates, router console, setup services and settlement topics

I traced all 34 panels in agentbox topics 28, 29, 30, 31 and 32 against the source at agentbox `c57d9c0508f4`. All five topics carried the stamp `6500582dfae2`, which is 120 commits behind the pin, and every topic had moved citations, so I restamped all five and re-resolved every citation. Results: 6 panels accurate, 2 accurate-with-limits, 26 corrected, and none left inaccurate. Most corrections were line moves in `agentbox.toml`, `config/entrypoint-unified.sh`, `flake.nix` and the governing documents. Seven were wrong claims, not just moved lines. The most important: AB-28.9 had `dream-engine` and `headroom-napi` under the ADR-2030 permissive licence, but both are `AGPL-3.0-only`. AB-31.7 drew the spend key `k_spend` as derived from `k_id`, but the code mints it as an independent key. Three citations were already wrong at the old stamp (AB-28.3 `agentbox.toml:1632`, AB-28.8 `entrypoint-unified.sh:2437-2442`, AB-28.10 `tui_read.rs:127`), which shows that the earlier cite-check passes checked line shape, not meaning.

## Findings

**W3H-01: AB-28.9 got the licences of two crates wrong (corrected).** The diagram showed `dream_engine` and `headroom_napi` as subclasses of the ADR-2030 `PublishableServiceCrate` (dual MIT/Apache). At the pin, `dream-engine` declares `AGPL-3.0-only` because it links `nostr-bbs-core` (`services/LICENSING-NOTICE.md:14-20`, `:46`; `services/dream-engine/Cargo.toml` `license = "AGPL-3.0-only"`). `headroom-napi` sits under `crates/`, not `services/`, and also declares `AGPL-3.0-only` (`crates/headroom-napi/Cargo.toml:8`). The impact: anyone reading the panel would think these two crates can be published under permissive terms. The same panel also said `agentbox-ops` has 12 binaries and 9 modules; the pin has 15 and 12 (`services/agentbox-ops/src/bin/`, `src/lib.rs` `pub mod`). It also said every crate is in the package set only when its gate is on, but only `dream-engine` is gated (`flake.nix:1761-1768`). `agentbox-manifest`, `agentbox-ops` and the knowledge-tool crates are always baked (`flake.nix:1749-1752`, `:1770-1774`, `:1793-1812`). I redrew the panel with an `AgplException` class and added a Drift marker. AB-28.13 L2 had the same wording and is corrected too.

**W3H-02: AB-31.7 drew `k_spend` as derived, but the code mints it independently (corrected, Tension recorded).** The panel showed `k_id → derive_subkey("sidestr/spend/…") → k_spend`. The built module mints `k_spend` "from an independent random seed … never derived from `k_id`" (`management-api/lib/sidestr-spend-key.js:7-12`), and ADR-2097 as amended says the same (`docs/adr/ADR-2097-sidestr-rail-supersedes-lightning-first.md:101-102`). So does the protocol registry (`docs/PROTOCOL-registry.md:174`). The identity governing document still gives the derivation and "the derived spend pubkey" (`docs/INGRESS-identity.md:507`, `:520`). ADR-2101, whose D3/D4 the module implements, still says `implementation_status: none`. To close it: amend INGRESS-identity's key table and ADR-2101's status to match what was built.

**W3H-03: AB-31.8 said the kind allocation was not fixture-backed; it now is (corrected).** At the pin, `38420`-`38425` are `allocated-proposed` rows in `schema/federation-kinds.json` (`docs/PROTOCOL-registry.md:188-192`). I replaced the old **Open** with a Drift marker plus a narrower Open: the fixture rows back the kind numbers, but nothing cited shows that a decoder round-trips an upstream event.

**W3H-04: AB-32.5 lists the chain URN and the 38420 binding as unbuilt, but both now exist in code (Drift recorded).** `config/sidechain/README.md:190-194` and the P1 status row (`docs/proposals/sovereign-settlement.md:337`) still list the `chain`/`asset` URN kinds and the 38420 binding under "not yet". `management-api/lib/uris.js:128` defines the `chain` kind, and `sidestr-spend-key.js:16-19` builds the binding. The `asset` kind is still absent. To close it: amend the README's "Not yet built" section.
