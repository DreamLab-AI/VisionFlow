# VisionClaw ontology pipeline, corpus ingest, data authority and identifiers

I assessed all 37 panels of VisionClaw topics VC-20 (ontology pipeline), VC-21 (corpus ingest), VC-22 (data authority, provenance and erasure) and VC-23 (identifiers) by source tracing at VisionClaw `86cdd7635582`, agentbox `c57d9c0508f4` and ontomark `4b9d15df4805`. All four topics were restamped from VisionClaw `8692b12ba987` (ontomark `560e50c1a35b`, agentbox `6500582dfae2`), and every citation was re-resolved and read at the pins. Results:

- 11 panels are accurate.
- 24 were corrected.
- 2 are accurate with limits.
- None is inaccurate and left unfixed.

The most important finding is in VC-20.7, which called the `/api/ontology-agent` scope "anonymous". It is not. The scope sits inside the `/api` scope wrapped by `RbacGate`, so every POST on it, `/propose` included, needs `WriteGraph` before the handler runs. Every GET is public only while `RBAC_PUBLIC_READS=1`. Four other mechanism errors were corrected:

- The ontology-physics toggle that does not gate its endpoints.
- A pipeline materialisation path that skips the shared vacuous-axiom filter.
- A decision fan-out drawn as writing `GRAPH_PROVENANCE` that never does.
- A Concept URN "live emission" that is a test fixture.

## Findings

**F1. `/api/ontology-agent` is not anonymous (VC-20.7, corrected).**
- *Trigger:* any POST to `/api/ontology-agent/*`.
- *Consequence:* the panel and ADR-2116's note said every route there needs no auth. `required_level` returns `WriteGraph` for every non-safe method outside the public allowlist (`src/middleware/rbac_gate.rs:179-189`; allowlist `:55-61`). The scope is configured inside the `/api` scope wrapped by `RbacGate` (`src/main.rs:1137`, `:1199`). An anonymous caller is therefore refused before `discover`, `query`, `check` or the 410 `propose` handler is reached. Safe reads are public only when `RBAC_PUBLIC_READS` is truthy (`rbac_gate.rs:135-141`, fail-closed). The same rule applies to `/api/ontology/class-count` and every public GET drawn in this panel.
- *Two further code-level drifts:*
  - The constructor comment says `RBAC_PUBLIC_READS` is "default on" (`rbac_gate.rs:200`), contradicting the fail-closed function above it.
  - `main.rs:1202` still says `/decisions/record` "is authed like /propose".
- *What closes it:* a route-level test that drives an anonymous POST through the real `/api` scope. Then either amend ADR-2116's wording or allowlist the read-only agent POSTs deliberately.

**F2. The pipeline materialisation path is not drift-proof (VC-20.4, corrected).**
- *Claim:* the `select_inferred_edges_for_sync` docstring says the sync path and `OntologyPipelineService` "cannot drift" (`src/services/github_sync_service.rs:1121`).
- *What the code does:* PATH B builds its own ancestor map (`src/services/ontology_pipeline_service.rs:492-505`). It calls `immediate_inferred_parents` (`:506`) rather than the front door `immediate_parents_from_subclass_pairs` (`src/services/inferred_edge_materialiser.rs:173-196`). As a result:
  - The `owl#Nothing` / `owl#Thing` filter (`inferred_edge_materialiser.rs:169-171`) never runs on that path.
  - It resolves through `get_nodes_by_owl_class_iri` and takes the cross-product of ids, not `IriNodeResolver`.
  - It writes no `source_iri` / `target_iri` metadata.
- *Shared:* only `select_inferred_edges` and `build_inferred_edge`.
- *Consequence:* none today, because PATH B hangs off `on_ontology_modified`, which nothing outside `tests/integration/pipeline_test.rs` calls. The existing Debt marker in VC-20 stands. If PATH B is wired up, it would materialise vacuous `owl:Thing` parents.
- *What closes it:* route PATH B through `immediate_parents_from_subclass_pairs`, or delete PATH B with its only caller.

**F3. `Settings.ontology_physics` does not gate the ontology-physics endpoints (VC-20.4, corrected).**
- *Claim:* the panel said the bool gates `POST /api/ontology-physics/enable|disable`.
- *What the code does:* both handlers call `check_ontology_feature`, which returns `Ok(())` unconditionally (`src/handlers/api_handler/ontology_physics/mod.rs:80-81`). The bool is read only to push ontology constraint weights from the quality-gate route (`src/settings/api/settings_routes.rs:1352`).
- *What closes it:* either make `check_ontology_feature` read the setting, or record that the endpoints are always live.

**F4. A plain page with an `owl-class` is classified as knowledge, not ontology (VC-21.3, corrected, Tension added).**
- *What the code does:*
  - `create_page_node` sets `node_type = ontology_node` (`src/services/parsers/knowledge_graph_parser.rs:198-202`) but always sets `metadata["type"] = "page"` (`:149`).
  - `Node::population_type` reads `metadata["type"]` first (`crates/visionclaw-domain/src/models/node.rs:271-276`), so `classify_node` puts the node in `knowledge_node_ids` (`src/actors/graph_state_actor.rs:261-265`).
  - The parser comment promising downstream reclassification (`knowledge_graph_parser.rs:164-165`) describes a fallback arm such a node never reaches.
- *Limit:* the panel previously implied ontology classification. Whether the persisted metadata survives the Oxigraph round trip unchanged was not checked at runtime.
- *What closes it:* a classification test over a real `owl-class` plain page, then either set the metadata type or correct the comment.

**F5. The decision fan-out writes nothing to `GRAPH_PROVENANCE` (VC-22.8, corrected).**
- *Claim:* the panel drew `SUM->>PROV: prov:wasGeneratedBy`.
- *What the code does:* the marker quad is written into `:summary` (`crates/visionclaw-adapters/src/oxigraph_ontology_repository.rs:821-827`, graph `GRAPH_ONTOLOGY_SUMMARY`). `append_derived_summary` routes only through `append_derived_quads` (`:841`), and neither `enrichment_proposals_handler.rs` nor `ingest_writeback_handler.rs` emits a PROV activity.
- *Consequence:* an approved enrichment leaves no entry in the append-only provenance ledger ADR-2016 describes; only the SQLite decision row and the summary marker exist.
- *What closes it:* emit a PROV activity through `emit_provenance` on the decision path, or state the omission in ADR-2016.

**F6. No production code mints a Concept URN (VC-23.10, corrected).**
- *Claim:* the panel cited `precedent_registry.rs:88` as the "live emission".
- *What the code does:* that line is inside `#[cfg(test)]` (`src/domain/broker/precedent_registry.rs:68`). A search of `src/` and `crates/` at the pin finds no non-test call to `uri::concept`.
