# Audit wave 4 — cross-repository wire contracts

I assessed 36 cross-repository contracts at the pinned revisions: 13 agree, 18 disagree and 5 cannot be verified from source. Only one contract, the federation kind map, has a fixture shared by both sides. Everywhere else each side tests against a hand-written copy of the other, and two of the breaks below pass their tests for that reason. W2-01 still holds at the pins, and it is not the first failure on that path. The agentbox forwarder opens VisionClaw's `/wss/agent-events` with no credential, so the server returns 401 before any frame is checked; that holds in release builds and, by default, in the dev stack (CONTRACTS-F1). Where the socket is accepted, every frame is refused as malformed and the refusal is dropped silently (F2). Even the canonical envelope would fail for authority-denial events, which carry string ids (F22). The VisionClaw → agentbox Management API has three response-shape breaks. Fastify response schemas strip fields that VisionClaw's serde structs require, so `list_tasks`, `get_task_status` and `get_system_status` cannot deserialise a real reply (F3–F5). On the governance wire, every producer sends kind-31402 `priority` as a label and the relay parses it as an integer, so every case projects at priority 50 (F6). The agentbox governance-bridge also omits the tags the relay projects (F7). The relay and the host apply the rationale gate to different outcome sets (F21). The pinned dependencies show lagging versions and two unpinned cross-repository path dependencies (F11–F16). Evidence class: source tracing at the pinned revisions. No runtime, test or deployment evidence was produced, and no test was run.

### Notes on the leading findings

- **F1 refines W2-01.** At the pins the live forwarder fails in this order. (1) The upgrade carries no `Authorization` header and no `?token=`: `agentbox:management-api/utils/agent-event-ws-subscriber.js:94`, and the URL derived at `agentbox:management-api/server.js:383` carries none either. VisionClaw therefore answers 401 (`VisionClaw:src/agent_events/ingest.rs:291-292`). (2) Only where `ALLOW_INSECURE_DEFAULTS` is honoured (`:59-68`) and set does the bare event reach `process_frame`, where it fails as `Malformed` (`:101,149`). (3) Even a canonical `createMcpNotification` frame (`agent-event-publisher.js:305-342`) fails for authority-journal events, which carry string ids (F22). A working edge needs a credential, the canonical envelope and integer ids.
- **F3–F5 come from one mechanism.** agentbox's own comments say fastify strips any reply field its response schema does not declare (`agentbox:management-api/routes/tasks.js:129-130,178-179`). VisionClaw's structs have no `#[serde(default)]` on `task`, `provider`, `status`, `task_dir`, `log_file` or `pid`, so each reply fails whole instead of degrading.
- **F6 affects the estate's own reference producers.** VisionClaw, the dream engine and the forum's own governance probe all send labels; nothing in the pinned code sends an integer.
