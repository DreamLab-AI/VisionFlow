# Agentbox identity, tab0-bridge and Nostr topics

I assessed all 44 panels of three agentbox topics by source tracing at agentbox `c57d9c0508f4`: AB-11 (identity, DID, URN, mandate, authority), AB-12 (tab0-bridge and the interaction plane) and AB-13 (Nostr relay, gateway, pod bridge, session mirror). All three were restamped from `6500582dfae2`. Result: 33 panels corrected, 9 accurate, 2 accurate with limits, none inaccurate and unfixed. 58 Mermaid citations, plus several prose ones, only needed renumbering after upstream edits. The more important corrections are about mechanism.

The most important finding is in the mandate model. AB-11.7 to AB-11.9 drew mandates being published to relays and revoked there. In fact nothing in agentbox publishes a mandate event at this revision. Revocation rewrites only the local registry, and leaves in force the pod `.acl` grant that the caller wrote. Several other mechanism claims were also wrong, and three of them were already wrong at the old stamp:
- the pod signer's default identity (AB-11.13);
- the CLI line numbers in AB-11.3;
- a doc-drift claim about the gateway user guide (AB-13.8).

One drift claim had been fixed upstream: the relay-consumer signature check now fails closed (AB-13.7).

## Findings

**1. Mandates are never published, and revocation does not reach the pod.**
- *Trigger:* `POST /v1/mandate` signs a kind-30078 event and returns it in `signed_event` (`management-api/routes/mandate.js:230`). `revokeMandate` re-signs the record and rewrites the registry (`management-api/routes/mandate.js:254-280`).
- *Consequence:* outside the two mandate modules, kind 30078 appears only in relay kind lists and in `routes/voice-intent.js:108`. That route consumes a mandate the caller supplies; it does not publish one. No code sends a mandate to a relay, so the NIP-33 replace-to-revoke design only works if an operator publishes the events by hand.
- *Consequence:* revocation never touches the `.acl` the caller PUT from `acl_turtle` (`management-api/lib/mandate.js:129-152`). WAC at the pod therefore keeps granting access after a revoke.
- *Closed:* AB-11.7 and AB-11.8 now draw exactly what is returned and written, and carry an **Open** marker (distribution) and a **Tension** marker (registry versus enforced ACL). Closing the defect itself needs a publish path and an ACL rewrite or removal on revoke.

**2. Unsigned mandates are never re-signed, and a re-mint is a new identity.**
- `ensureMandate` reuses any active registry entry whether it is signed or not (`management-api/routes/mandate.js:171`). `isMandateActive` ignores `signed` (`management-api/lib/mandate.js:191-198`).
- The URN content-addresses a record that includes `issued_at` (`management-api/lib/mandate.js:107-124`). So the "re-mint once the signer is restored" advice in the warning (`management-api/routes/mandate.js:214-219`) produces a new URN and `d` tag. The old registry entry is overwritten, not signed.
- AB-11.9 had shown an UnsignedRegistered → SignedActive "re-published" edge, which no code implements. The edge is replaced, and a **Drift** marker is added.

**3. The pods adapter signs as the container's sovereign identity, not the agent's profile DID (AB-11.13 redrawn).**
- *Old drawing:* stack selection read `AGENTBOX_PROFILE`, and with no stack the build returned null and aborted.
- *At the pin:*
  - `AGENTBOX_PROFILE` no longer selects a stack (`management-api/lib/pod-signer.js:21-26`, `:79`).
  - With no stack named, the default is `loadSovereignSigner`, which loads the bootstrap identity (`:98-99`).
  - An identity-port branch applies under role isolation (`:76-77`, `:132-136`).
  - A request that already carries an `Authorization` header skips signing in both modes (`management-api/adapters/pods/_solid-http-base.js:81-82`).
- *Tension:* the per-session mandate grantee (`management-api/routes/sessions-boundary.js:294`) is not the key that adapter writes are signed with by default.

**4. The agent-identity CLI citations were wrong at both revisions (AB-11.3).**
- `main` sits at `management-api/lib/agent-identity.js:298-331`, not `:201-233`. The old lines fell inside `sovereignIdentityPath` and `loadSovereignSigner`, and AB-11.13's `:232` reference to `loadSovereignSigner` already contradicted them.
- The entrypoint ranges are re-derived (`config/entrypoint-unified.sh:1424-1450`). They now include the canonical-DID refusal (`:1445-1448`) and the fact that the entrypoint, not the CLI, derives the exported PUBKEY and MULTIKEY (`:1449-1450`).
- The INGRESS-identity drift note moved to `docs/INGRESS-identity.md:229-231`. It cites `agent-identity.js:175`, which is a `pubkey` field and not a fallback. That is recorded in the existing **Drift**.

**5. The URN grammar grew two kinds the panels did not show (AB-11.1, AB-11.4 to AB-11.6).**
- `KINDS` has 21 entries, not 19: `knowledge` (ADR-2085, `management-api/lib/uris.js:115`) and `chain` (ADR-2098, `:128`).
- `chain` carries a `localGrammar` that `mint`, `parse`, `isCanonical` and `resolveCanonical` all enforce (`:191-200`, `:304`, `:313-318`, `:284-286`). All four panels now draw it.
- **Tension (AB-11.15):** `resolveCanonical` hands out surfaces for `decision`, `knowledge` and `agent`, but the resolver has no case for them and answers 404 (`management-api/routes/uri-resolver.js:155-162`).

**6. The relay-consumer I01 drift is resolved at the pin (AB-13.7).**
- `_verifySig` now requires `verifyEvent(event) === true`, and returns false on any load or verifier error (`mcp/nostr-bridge/relay-consumer.js:743-756`). The structural-acceptance fallback is gone.
- The panel note is now marked RESOLVED. I did not edit AB-40.
- **New Tension, with real exposure under the shipped defaults:** under the `allowlist` policy, an empty allowlist admits every signed author (`mcp/nostr-bridge/relay-consumer.js:764-768`), the opposite of the Rust deny-all.
  - Nothing in `flake.nix`, the entrypoint or the manifest projector sets `AGENTBOX_RELAY_ALLOWED_PUBKEYS`.
  - The shipped manifest sets `external_fanout = "bidirectional"` (`agentbox.toml:175`), which `flake.nix:4515` projects into `AGENTBOX_RELAY_FANOUT`. Any value other than `off` adds the public relays in `NOSTR_RELAYS` to the subscription (`relay-consumer.js:247-255`). The image default for that is damus and primal (`flake.nix:4321`).
  - `AGENTBOX_NPUB` comes from bootstrap's identity.env (`services/nostr-pod-bridge/src/bootstrap.rs:205`), so the consumer does start.
  - *Consequence:* any signed author on those relays whose event p-tags a local npub reaches the governance, intent and payment handlers. The authority gate's own responder allowlist (`management-api/lib/authority-consumer.js:259-271`) still guards 31403 approvals.
  - *What would close it:* deny-all on an empty list, or projecting `[sovereign_mesh.relay].allowed_pubkeys` into `AGENTBOX_RELAY_ALLOWED_PUBKEYS`.
  - Whether a deployment overrides these settings is runtime configuration, not visible from source.
