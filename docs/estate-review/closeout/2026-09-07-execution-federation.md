## Publisher changes and evidence

[visionGraph build](../../../../visionGraph/pipeline/build.py) and [knowledgeGraph build](../../../../knowledgeGraph/pipeline/build.py) use identical [public projection](../../../../visionGraph/pipeline/public_projection.py) code. The preflight accounts for recursive Markdown inputs before a permissive parser can discard malformed fences. Non-boolean or conflicting publication flags block output. The projection removes known private identities from typed relations, prose and raw JSON, including parseable excluded dot/held pages. A private intermediate node cannot generate inferred ancestry between otherwise public endpoints.

The shipping [visionGraph workflow](../../../../visionGraph/.github/workflows/publish.yml) previously copied raw source Markdown after the build. That would have bypassed a safe graph exporter. The canonical build now generates title-form Markdown and namespace aliases from projected fields; the raw-copy loop is removed. knowledgeGraph retains compatible slug mirrors and adds the same protected title-form mirrors. Released census and validation details are aggregate-only; local authoring tools retain diagnostic APIs.

The builder stages a complete generated bundle and uses backup/rename promotion. A failed second tree installation restores the prior output, tested byte-for-byte. If the filesystem also prevents rollback, the code reports failure and retains its recovery directory. This is not simultaneous atomic activation for live readers. Static root assets are preserved.

## Trust and governance changes

[trust_sweep.rs](../../../../nostr-rust-forum/crates/nostr-bbs-relay-worker/src/trust_sweep.rs) guards level, admin exemption, nullable activity/update timestamps and all activity/moderation counters. Its immediately following audit INSERT selects only when the preceding UPDATE changed one row. Both results must report one change. A concurrent policy change therefore yields neither demotion nor a false audit fact.

[receipts.rs](../../../../nostr-rust-forum/crates/nostr-bbs-relay-worker/src/relay_do/receipts.rs) binds each ordinary response plan to its signed event, request, case, signer and outcome. The decision SQL requires the observed request and legal state, matching latest decision, and incomplete receipt. Case and receipt updates require the previous statement's changed-row count; all three writes are checked. [nip_handlers.rs](../../../../nostr-rust-forum/crates/nostr-bbs-relay-worker/src/relay_do/nip_handlers.rs) rejects absent request cases and unknown persisted states, checks completed receipts before planning a now-terminal case, and does not replace/reset a case on request redelivery.

[Eight exact production-SQL tests](../evidence/execution-2026-09-07/forum-sql-transactions-after.log) exercise SQLite transactions rather than a fake SQL implementation: zero-row, changed request/state/activity/admin, latest-decision race, duplicate commit, null snapshot, and rollback after injected audit/receipt failure. [241 native relay tests](../evidence/execution-2026-09-07/forum-receipts-after.log) and [wasm32 worker compilation](../evidence/execution-2026-09-07/forum-wasm-after.log) pass. No live D1 instance was mutated.

EA-04 now also extends the consumers. Agentbox signs the exact canonical operation and digest, refuses changed signed content, and matches only the exact request event; case/panel identifiers never substitute for that reference. The broker bridge creates an immutable durable received claim before sending the approved payload, then records applied only on an actual upstream committed acknowledgement. Duplicate, incomplete and uncertain claims refuse blind replay. The [Agentbox contract](../../../../project/agentbox/docs/developer/governance-operation-receipts.md) distinguishes this local unsigned ledger from the older best-effort provenance file and from the separate in-memory grant-revocation path.

VisionClaw persists the exact signed request before publication, verifies signature/request/d-tag agreement on response, and persists one dispatch claim before actor delivery. Decision-elevation signs the actual draft/path, refuses unavailable durable storage, and conditionally claims an approved case before calling GitHub. An uncertain `applying` row is not retried or expired automatically after restart. The [VisionClaw contract](../../../../project/docs/explanation/governance-operation-receipts.md) records offline-history, legacy-request migration and manual-reconciliation limits. A dispatch record is not proof that the actor ran; a PR URL is not a merge or activation receipt.

[21 Node tests](../evidence/execution-2026-09-07/agentbox-governance-after.log) and [29 Jest tests](../evidence/execution-2026-09-07/agentbox-authority-after.log) cover mismatched/ambiguous requests, altered operations, refusal, timeout, storage failure, restart and duplicate execution. Their upstream acknowledgement is injected, not a live mutation. [The final Rust suite](../evidence/execution-2026-09-07/visionclaw-governance-after.log) reports **1,369 passed, six ignored** and covers signed-request tampering, durable dispatch, conditional application claim and uncertain-outcome restart policy. No live D1, human approval or GitHub mutation was performed. Separate supersession/appeal paths and responder provisioning must not inherit this local ordinary-response validation.
