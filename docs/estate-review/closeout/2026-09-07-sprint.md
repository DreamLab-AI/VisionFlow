## Closure evidence

For each row, retain one reviewable receipt with:

1. The finding/ADR and exact source/build/configuration identity.
2. The original failing input and observed result, including successful no-op writes.
3. The implementation change and passing positive/negative/recovery tests on the correct consumer.
4. The deployment/target receipt if activation is claimed; source tests alone leave activation staged.
5. The ADR and governing-document correction plus the master TODO closure link.

A supported release can explicitly exclude an optional profile. That requires a recorded scope decision and disabled/rejected entry path, not an assumption that nobody uses it. Historical narrative, speculative research and unused upstream packages retain lineage without blocking an unrelated release. Any consumer that adopts them reopens their relevant acceptance obligations.

## Six acceptance journeys retained

Use the [programme's full contracts](README.md#system-acceptance-journeys): author→grounded answer; request→human decision→applied change; owned data→revocation→recovery; action→rendered state; learning→reviewed improvement; release→operation. Each needs negative and recovery cases with component identity. A published diagram, passing unit suite or generated index cannot close these journeys.
