# Agentbox Loom, ontology, headroom and media topics

This review covers all 42 panels of agentbox topics AB-24 (Loom facade), AB-25 (ontology tools and governed writes), AB-26 (headroom, beads, typed spawn, RuvNet grounding) and AB-27 (media and GPU capability services). All four topics were stamped at agentbox `6500582df`, 120 commits behind the pin. I restamped each one to agentbox `c57d9c0508f4`, and AB-24 also to VisionClaw `86cdd7635582` and loom `ba21a689a57d`. I re-resolved every citation at those revisions and read every panel against the pinned source. Results: 4 panels accurate, 2 accurate with limits, 36 corrected, none left inaccurate. Most corrections are line moves in `agentbox.toml`, `flake.nix`, the entrypoint and `agentbox.sh`, but some were substantive. Three findings matter most. The typed-spawn MCP tools fall back to an in-memory beads database on every call by default, so `spawn_ready` and `spawn_complete` cannot see what `spawn_child` made. The three headroom MCP tools are defined, but no server loads them. Headroom compression has exactly one caller, the memory search route; the diagrams had claimed adapter middleware. The corrected panels also no longer misstate ADR-2074 (it is now *rejected*), the loom-mcp `isError` contract, and the condense refresh, which never writes to RuVector.

## Findings

**W3G-01: typed spawn defaults to a throwaway database (AB-26.7, Tension).**
- *Trigger:* `AGENTBOX_BEADS_DB` is unset, which is the shipped default.
- *Consequence:* the handler comment promises a "persistent beads.db so ready/complete see prior state" (`mcp/servers/substrate-tools.js:167`). In fact the MCP registration defaults the variable to empty (`mcp/mcp.json:224`), and `loadDeps` maps an empty path to `:memory:` (`mcp/servers/lib/typed-spawn.js:31-35`) before the adapter's own `$WORKSPACE/beads.db` default can apply (`management-api/adapters/beads/local-sqlite.js:63-64`). Each tool call builds a new context (`substrate-tools.js:169,174,178`), so `spawn_ready` returns nothing and `spawn_complete` cannot find a bead from an earlier call. A `spawn_child` that passes an `epic_id` from an earlier call fails outright, because `createChild` on an unknown parent raises NotFound (`tests/contract/beads.contract.spec.js:192`). Only an epic-less first call succeeds, and its state is lost when the call returns. Source tracing only; no tool was called.
- *To close:* default `loadDeps` to the workspace database, or set the variable in the registration. Add a test that spans separate tool calls.

**W3G-02: the headroom MCP tools are unreachable (AB-26.3, Debt).**
- *Evidence:* `management-api/lib/headroom-mcp-tools.js:89-93` and `:111` define and dispatch `headroom_retrieve`, `headroom_stats` and `headroom_compress`. A repository-wide grep at the pin finds no other reference to the module except an archived ADR and an archived PRD.
- *Consequence:* a CCR sentinel in a compressed memory result has no agent-facing way back to its original. The handlers also call `smartCrush`, `compressLog` and `compressDiff` directly, so no slot gate applies (`headroom-mcp-tools.js:166-186`).
- *To close:* register the tools on a served MCP surface, or delete the module.

**W3G-03: compression has one caller, not a middleware layer (AB-26.1, AB-26.9, Tension).**
- *Evidence:* the only `compress()` call in management-api is the memory search route (`management-api/routes/memory.js:269-280`). No file under `management-api/middleware/` references headroom.
- *Consequence:* the `pods` and `beads` slot switches (`agentbox.toml:2506`, `:2508`) have no caller. AB-26.1 and AB-26.9 N3 had drawn compression inside the adapter dispatch chain; both are corrected.
- *To close:* wire the pods and beads callers, or drop those switches and the "every adapter slot" comment (`headroom.js:13-14`).
