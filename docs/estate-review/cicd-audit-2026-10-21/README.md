Checked 21 October 2026. Scope: the fourteen website-listed/directly linked VisionFlow repositories used in the README refresh. PHP is excluded at the user's request. This is an audit and a remediation plan; none of the tasks below has been applied.

The primary sites are reachable and their latest Pages deployments succeeded. Five DreamLab Worker health endpoints return HTTP 200. That does not make the estate's CI green: current haptic and plugin checks fail, Solid's last source CI fails in coverage, and Agentbox/VisionClaw have significant gaps between source and observed CI execution.

[Evidence snapshot](evidence.json) contains the fourteen repository heads, all 55 registered workflows, latest observed runs, deployment records, releases, policy results and thirteen HTTP probes. Raw API responses and failed-job logs are retained locally at `/tmp/visionflow-cicd-audit-20261021/`. Signed release-download query strings were excluded from the saved evidence.

## P1: restore trustworthy checks and release readiness

- [ ] **CI-01 — Repair plugin WASM/native parity and verify release provenance.** Owner: ontomark-obsidian, with Ontomark engine support. [Current failure](https://github.com/DreamLab-AI/ontomark-obsidian/actions/runs/39594897119) reports two failures at `test/wasm-harness.test.mjs:68,75`: built WASM reports engine 0.4.0 while the expected transcript reports 0.2.2, with changed fixture counts and output. Reproduce from a clean install, generate the native transcript from the exact engine pin and fixture set, review semantic differences, and regenerate both WASM targets and the golden together. Preserve strict byte-parity checks. **Done when:** build, unit, WASM, bundle and offline gates all pass in CI, and a clean package's hashes match its release assets. [Tag 0.3.6 release failed before publication](https://github.com/DreamLab-AI/ontomark-obsidian/actions/runs/39022251141); investigate how its four existing assets were produced rather than assuming this job published them. Do not silently replace released bytes.

- [ ] **CI-02 — Re-verify the haptic membership ADR against the published README.** Owner: visiontouch-rs. [Failure](https://github.com/DreamLab-AI/visiontouch-rs/actions/runs/39595196249): `ADR-0006-estate-membership-lab-evaluation.md` still verifies `990beb0`, but governed `README.md` changed in `08c6f1b`. The README publication caused this staleness; it is not an unrelated inherited failure. Review that the lab/private/hardware boundaries still hold, then update the ADR's verification metadata against the published change. **Done when:** the full hardware-free quality gate and remote CI pass at the remediation commit. No physical device session is needed or authorised by this item.

- [ ] **CI-03 — Diagnose Solid's instrumented coverage crash.** Owner: solid-pod-rs. [CI failure](https://github.com/DreamLab-AI/solid-pod-rs/actions/runs/39349489580) is `cargo_tarpaulin: A segfault occurred while executing tests`; `CI required` correctly propagates that failure. Isolate the failing test binary, runner/toolchain and tarpaulin configuration; distinguish a product crash from an instrumentation fault. **Done when:** required coverage completes on the supported runner and the aggregate check is green, with the cause recorded. Keep the required check; do not blanket-disable coverage to turn it green.

## Execution order and acceptance

Start CI-01/02/03 in parallel only if separate workers/checkouts are explicitly assigned. Resolve CI-04/05 before relying on large source histories as validated; then re-run CI-06 and rehearse CD-01. Refresh CI-07, reconcile CD-02, and apply CI-09 only after the required checks work. Optional mirrors and historical records should never block a healthy primary deployment by accident.

No current public outage was established by these checks. The six primary-surface probes returned HTTP 206 because the audit deliberately used range requests; the sites, namespace, JSON stats and release asset were reachable. The five Worker health probes returned 200. DNS failures were confined to optional/unconfirmed mirror hostnames. Neither a health response nor a green workflow proves an authenticated user journey, host GPU/headset acceptance or exact running-source equivalence.

The audit did not dispatch workflows, publish releases, activate containers, change repository policy, provision credentials or create GitHub issues. The unchecked items are the remediation TODO list, not completed fixes.
