# Dream execution, repair egress and triage evidence

Apply repair can send committed text to the model even when the normal source stage would withhold the file. Two probes exercised the real adapter candidate flow with failed patches: the repair prompt contained harmless canaries from a denylisted filename and from a file recognised as carrying key material. The model was a capturing stub; no credential was read and no request left the process.

This pass assesses AB-23.1, 4, 5, 8, 18 and 22, completing the source review of this topic's 22 original panels across the linked passes. It also assesses all sections and rereads of ADR-2114. ADR-2155 is read for the dream consumer only; its other consumers and activation procedure remain outside this pass. The engine's nested diagram corpus, open implementation findings and the wider estate audit remain outstanding. Production code and ADR status fields are unchanged.

| AB-E6 / high when old work is still active: retention has no liveness protection | `engine.rs:806-810` removes matching directories by parent mtime alone. The exact command deletes a six-day-old fixture parent containing a freshly written child. Test a long-running job whose parent mtime remains old. The fixture is a model of the condition, not an observed production race. |
| AB-E7 / medium: cleanup failure is reported as success | The same command redirects stderr and ends with true. | AB-E8 / medium, source-level liveness risk: connected SSH has no overall deadline | `dispatch.rs:39-60` configures ConnectTimeout=10, writes stdin and waits synchronously for output. Retention and health occur before begin but after taking the per-night lock. | Add a command deadline, terminate/reap the process group, and report timeout separately. Test connected hangs and stalled writes. This pass did not induce a hung process or a live scheduler stall. |

Positive controls matter here. The actual health function writes/removes a probe file, rejects an unwritable target, accepts a scripted 12 GiB at a 10 GiB floor, rejects it at 13, and rejects a failed df. Zero capacity floor does not disable the write test. Disabled triage makes no transport calls. A valid triage response never directly grants ACCEPT: only a configured support threshold can skip candidate execution, leaving an unproven result.

## Dream triage within ADR-2155

Current manifest settings enable System One and dream triage, selects typesafe, and leaves system_one.local_only empty (`agentbox.toml:890-895,2651`). The projector derives DREAM_TRIAGE_LOCAL_ONLY from that list (`system_one.rs:551-577`), and the supervisor expression sets the triage flag only when the dream and proxy gates are enabled (`flake.nix:270-281`). No deferral threshold is configured in these inspected files. Locality is declared configuration, not inferred from URL shape. This inspection does not read live process environment or call the selected backend.

ADR-2155's Decision initially describes private local-only consumers; its 30 October amendment changes the default to the selected proxy backend, with explicit per-consumer local-only opt-in. Its Verification section and later rereads retain staged activation and explicitly distinguish transport acceptance from accuracy uplift. Those qualifications stand. The security follow-up documents redirects and timeout handling; the existing triage redirect test passes here, but it is not a retest of every consumer's stalled-body or credential-write path. The skill-list and state-budget rereads do not establish a triage accuracy benefit. Full consumer activation, memory fixtures and the local façade remain unassessed by this pass.

[SWE-agent's environment documentation](https://swe-agent.com/latest/config/environments/) describes Docker-based execution; it also now directs users to mini-swe-agent and labels SWE-agent maintenance-only. Dream-engine's inspected adapter instead uses a local formatter and a connected-node annexe. The useful comparison is where each subprocess runs and what it can modify; a product name or container alone is not a confinement proof.

[SWE-bench's evaluation guide](https://www.swebench.com/SWE-bench/guides/evaluation/) separates applying a patch, executing tests and reporting resolution, and retains per-instance patches, scripts, output and reports. It warns that reused run/instance identifiers can reuse old results even for a changed patch. That supports a concrete acceptance requirement here: bind every advisory and evaluation record to the exact attempted input, and expose stale/reused evidence. It does not establish that either system's tests prove every semantic requirement.

A useful near-term product is a nightly maintainer assistant that produces a bounded experiment and a reviewable draft. Validate that proposition on fresh, consented repository tasks with held-out expected outcomes. Compare triage off versus annotation versus calibrated deferral at equal model/evaluator budgets; report missed useful fixes, time saved, all egress paths and reviewer minutes. Add canary tests for every source-to-model route before promoting “private” or “source-read disabled” as user controls. This is a proposed evaluation, not a measured market ranking or benefit claim.
