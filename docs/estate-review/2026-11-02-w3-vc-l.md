# VisionClaw XR, Codescape, proposal and physics-hold panels

I assessed all 54 panels of fourteen VisionClaw topics: VC-40 to VC-46 and VC-48 to VC-54. The evidence class is source tracing at VisionClaw `86cdd7635582`, agentbox `c57d9c0508f4`, ontomark `4b9d15df4805` and Codescape `58108c0357bd` (see Verification for why Codescape keeps its own stamp). Every topic was restamped, and every citation was re-resolved at those revisions and read. Of the 54 panels:

- 6 are accurate.
- 9 are accurate with limits.
- 39 are corrected.
- None is inaccurate and unfixed.

The most important finding is that two hold mechanisms now contradict each other in the physics actor. The ADR-2169 spring-mode amendment has merged since VC-52 and VC-54 were drawn. While a node is held or settling, it forces the Verlet integrator. The `HOLD_GLOBAL_SPEED` floor applies over exactly the same span, but only the adaptive integrator reads it, so the floor is dead code. Its doc comment still describes the FA2 path.

The second finding is in the XR client. Since ADR-2159 replaced the exclusive backend switch, the Codescape volume never receives the Codescape colour palette. The XR client doc still claims it does.

## Findings

**W3-VC-L-01: the hold speed floor has no reader (Debt, VC-52.3 and VC-54.4).**
- **Trigger:** any node is held, or the 2 s settle window after the last release is open.
- **Mechanism:** `step_overrides` raises `global_speed` to `HOLD_GLOBAL_SPEED` (2.0) and sets `elastic_overlay` for the same condition (`src/actors/gpu/force_compute_actor.rs:4580-4581`, `:4587`). The overlay is applied every step (`:2015`). When the overlay is active, the GPU wrapper forces `adaptive_speed = 0` (`src/utils/unified_gpu_compute/execution.rs:1159-1160`). The only reader of `global_speed` is the adaptive branch (`crates/visionclaw-gpu/src/cuda_sources/visionclaw_unified.cu:1059`, `:1073`). The Verlet branch reads `dt` and damping (`:1088-1089`).
- **Consequence:** the floor and `StepOverrides::global_speed` are computed but never used. The constant's doc comment (`force_compute_actor.rs:4522-4531`) still justifies the floor as "the only stored parameter that moves the neighbours", which is no longer true. Stored damping, which VC-52.3 previously called inert, is now live in every hold window.
- **To close:** delete the floor, or fold it into the overlay's hold gain. Refresh the doc comment. Measure the two-second settle under spring mode on the live force set.

**W3-VC-L-02: the Codescape volume keeps the Domain palette (Debt, VC-40.3).**
- **Trigger:** both connections are up, and the Codescape volume is drawn.
- **Mechanism:**
  - The volume packs from its own connection's `BinaryProtocolClient` (`xr-client/scripts/connection_volume_source.gd:141`, `:149`).
  - That client's render store defaults to `ColorMode::Domain` (`xr-client/rust/src/domain_palette.rs:50`).
  - `apply_backend_palette` is called once, with `"visionclaw"`, on the client that `GraphParity` holds (`xr-client/scripts/graph_scene.gd:1353-1354`).
  - The `GraphParity` client is the VisionClaw client (`graph_scene.gd:1381`).
  - No code calls `set_color_mode` on the Codescape client. A `git grep` over `xr-client/` at the pin finds only the parity path and tests.
- **Consequence:** code nodes have no corpus domain, so they fall to the default domain swatch (`xr-client/rust/src/render_store.rs:2460-2469`) instead of the Codescape community palette. ADR-2159 D1 gives each connection its own palette (`docs/adr/ADR-2159-...md:37`), and `docs/XR-client.md:1127` says the default is selected "on every switch".
- **Limit:** source tracing only. No headset image was taken.
- **To close:** select `default_color_mode_for_backend(mode)` on each connection's client when it is built, and correct the doc.

**W3-VC-L-03: the retired exclusive switch is still documented, and one hook is orphaned (Drift and Debt, VC-40.2).**
- **Code:** `_switch_backend` is gone, and a GUT case asserts its absence (`xr-client/tests/unit/test_backend_switch.gd:32`).
- **Docs:** `docs/XR-client.md:1116` ("Switch hygiene") and ADR-2143 A6 item 4 (`ADR-2143-...md:346`) still describe it. `docs/XR-client.md:1000` correctly says `BackendConnection` replaced it.
- **Orphaned hook:** `graph_parity.on_backend_switched` (`xr-client/scripts/graph_parity.gd:493`) has no production caller. Only `test_graph_parity.gd:261` reaches it.
- **Panel:** VC-40 was a historical topic stamped at `e4ba5eb`, 280 commits behind. It is now redrawn at the pin. VC-40.1 shows the table and the per-volume gate, VC-40.2 shows where the switch's hygiene went, and VC-40.3 shows the palette gap above.
- **To close:** refresh both doc passages, and delete or rewire the hook.
