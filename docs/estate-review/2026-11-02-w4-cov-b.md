# Audit wave 4: loom component coverage

Coverage-detail lists 14 uncited loom components, 133 source files in all, and each now has one disposition. Six are assessed from source: `loom-scaffold`, `loom-graph-oxigraph`, `loom-backend-openai`, `loom-embed-xinference`, `loom-attest-proofgate` and `loom-client`. Two more are assessed with a lighter read: `scripts` and `model`. Three are covered elsewhere: `app`, `loom-bench`, and the pilot part of `bench`. Four are out of scope: `uplift-results`, `tools`, `legacy` and `bench`. None is left as a gap. The read found three medium findings:

- **COV-B-F1.** The read-only SPARQL clamp is a keyword regex over the whole query text. It therefore refuses any `/loom/search` whose needle contains `service`, `load`, `copy`, `add`, `create` or another blocked verb, with HTTP 400.
- **COV-B-F2.** The Xinference embedder cuts an error body at byte 200 with no character-boundary check. The workspace builds with `panic = "abort"`, and the embedder is probed at every façade start, so one non-ASCII error body can abort the façade process.
- **COV-B-F3.** The model engine runs on host networking and binds `0.0.0.0:8085` with no API key, although its overlay says "No new LAN port".

The loom repository has no topic set of its own. The corpus describes it only through the estate topics ES-01, ES-06 and ES-12 and the agentbox topic AB-24. Those topics still describe what loom is for, but none of them draws the adapter ring, the client, the bench or the model engine (COV-B-F11).

## Findings

- **COV-B-F1: the SPARQL write-verb clamp refuses ordinary label searches.**
  - **Class and severity:** defect, medium.
  - **Citation:**
    - `forbidden_re` matches `INSERT|DELETE|LOAD|CLEAR|DROP|CREATE|COPY|MOVE|ADD|SERVICE` as whole words, case-insensitive, across the entire query text, string literals included (`loom:crates/loom-graph-oxigraph/src/lib.rs:47-51`, `:85-90`).
    - `search_labels` lower-cases the needle and embeds it in a `CONTAINS` string literal (`:141-151`, `:331-335`), then sends it through the same `run` → `validate` path (`:256`).
    - `/loom/search` passes the client's `q` straight in (`loom:crates/loom-facade/src/routes/mod.rs:256`, `:261`), and the façade maps `BadQuery` to 400 (`loom:crates/loom-facade/src/error.rs:50`).
    - The integration tests search only "graph", "protocol" and "private working note" (`loom:crates/loom-graph-oxigraph/tests/integration.rs:97`, `:149`, `:199`), so this is untested.
  - **Consequence:** `q=service mesh`, `load balancing`, `copy` or `add-on` returns 400 "forbidden keyword" instead of hits. The same over-block hits `/loom/sparql` and MCP `loom.sparql` whenever a literal or an IRI segment such as `…:service-mesh` contains a blocked word. This is from source only; nothing was run. Fix: check the verbs against parsed query structure, or strip literals and IRIs before matching.
- **COV-B-F2: a non-ASCII Xinference error body can abort the façade.**
  - **Class and severity:** defect, medium.
  - **Citation:**
    - `truncate` slices `&s[..200]` with no `is_char_boundary` check (`loom:crates/loom-embed-xinference/src/lib.rs:130-137`). It runs on every non-2xx reply (`:167-173`).
    - The workspace release profile sets `panic = "abort"` (`loom:Cargo.toml:72`).
    - The façade spawns `verify()` on every start (`loom:crates/loom-facade/src/lib.rs:140-148`).
    - `loom-client` already fixed the identical bug with a boundary walk-back and a test (`loom:crates/loom-client/src/error.rs:134-145`, `:160-166`).
  - **Consequence:** if Xinference answers a probe or an embed with an error body longer than 200 bytes, and byte 200 falls inside a multi-byte character, the panic aborts the whole façade process, not one task. In serving this is reachable at boot. When semantic fallback is enabled, it is also reachable on query-time embeds. It is reachable in the `stage_corpus` bin too.
- **COV-B-F3: the model engine listens on every host interface with no key.**
  - **Class and severity:** security, medium.
  - **Citation:**
    - `HOST_ADDR` defaults to `0.0.0.0` (`loom:model/serve-qwen38.sh:19`) and is passed as `--host` (`:90`).
    - The argument list carries no `--api-key` and enables `--metrics --slots` (`:88-101`, `:98`).
    - The deployed overlay uses `network_mode: host` (`loom:deploy/compose.model-vision.yml:18`), and its environment sets no `HOST` (`:21-32`). No file under `deploy/` sets `HOST`.
    - The overlay's own header says "No new LAN port" (`:7`). The estate notes the model on `127.0.0.1:8085`, while ES-06 names `:8085` as an egress door (`docs/diagrams/estate/06-loom-and-email-privacy-path.md:67`) and AB-24 records a raw `:8085` path in use (`docs/diagrams/agentbox/24-loom-facade.md:95`).
  - **Consequence:** by source, any host that can route to the HP reaches the unauthenticated chat, slots and metrics endpoints directly, bypassing the façade's grounding and telemetry. Whether a host firewall or the NAT confines it cannot be checked from source. The estate's own descriptions disagree on whether `:8085` is host-local. Fix: set `HOST=127.0.0.1` in the overlay, or add `--api-key`.
- **COV-B-F4: loom-client can report a stale transient error instead of `Truncated`.**
  - **Class and severity:** defect, low.
  - **Citation:** a transient failure on the final attempt returns at once (`loom:crates/loom-client/src/client.rs:304-308`), so the loop only falls through after a truncated final attempt. `last_transient` is never cleared on a later truncation (`:296`, `:301-302`), yet the fall-through returns it in preference to `Truncated` (`:314-318`). That contradicts its own comment (`:312-313`). `Transport`, `Empty` and 5xx errors classify as transient (`loom:crates/loom-client/src/error.rs:121-124`).
  - **Consequence:** the sequence [transient, truncated, truncated] surfaces a transport-class error that `is_transient()` calls retryable. A caller doing its own scheduling then retries at the old budget instead of raising it.
- **COV-B-F5: the attestation chain detects corruption, not a capable tamperer.**
  - **Class and severity:** security, low.
  - **Citation:** entry hashes are an unkeyed SHA-256 over the previous hash and canonical JSON (`loom:crates/loom-attest-proofgate/src/lib.rs:149-166`). The head checkpoint is a plain JSON sidecar (`:229-245`). `verify_chain` trusts both (`:367-406`).
  - **Consequence:** anyone with write access to the ledger directory can rewrite any entry, re-chain the rest and rewrite `.head`, and `/loom/attest/verify` still reports `ok`. AB-24 presents `passed` as the record of "is this in the corpus because someone said so" (`docs/diagrams/agentbox/24-loom-facade.md:494`). That guarantee holds only as far as the filesystem's access control does. Signing or keying the head would be needed for non-repudiation.
- **COV-B-F6: a crash between append and head update reads as tamper.**
  - **Class and severity:** defect, low.
  - **Citation:** `attest` appends the line, then writes the head as a separate step (`loom:crates/loom-attest-proofgate/src/lib.rs:352-362`), with no fsync. `verify_chain` returns false when the tail and head differ (`:399-404`). A torn final line fails `read_entries` (`:296-297`), which every later `attest` calls first (`:314`).
  - **Consequence:** a crash or a full disk at the wrong moment leaves the ledger permanently reported as broken, or blocks every later attestation, until someone repairs it by hand. Each `attest` also re-reads the whole file (`:314`), so append cost grows with ledger length on a serving route.
- **COV-B-F7: proofgate still calls itself build/CI-time only.**
  - **Class and severity:** drift, low.
  - **Citation:** `loom:crates/loom-attest-proofgate/src/lib.rs:1-2` ("never on the serving hot path") and `loom:crates/loom-attest-proofgate/Cargo.toml:9`. In fact the façade's `attest` feature mounts it as a per-process serving dependency (`loom:crates/loom-facade/Cargo.toml:52`, `:67`; `loom:crates/loom-facade/src/state.rs:142`, `:178`), as AB-24 draws (`docs/diagrams/agentbox/24-loom-facade.md:476-478`, `:494`).
  - **Consequence:** a reader of the crate would assume no runtime exposure. F5 and F6 matter precisely because it is on the serving path.
- **COV-B-F8: the corpus and the model Dockerfile still name Qwen3.8-27B.**
  - **Class and severity:** drift, low.
  - **Citation:**
    - The deployed overlay has served Hemmingway-1.5 Q8_0 since 2026-10-29 (`loom:deploy/compose.model-vision.yml:1-3`, `:22`, `:27`).
    - `loom:model/Dockerfile:2` says "Serves Qwen3.8-27B on :8085".
    - The topics draw "Qwen3.8-27B" in the model box (`docs/diagrams/estate/06-loom-and-email-privacy-path.md:51`; `docs/diagrams/estate/01-estate-topology.md:112`; `docs/diagrams/agentbox/24-loom-facade.md:75`).
  - **Consequence:** the diagrams name the wrong model and omit the CC-BY-NC-4.0 licence the overlay records (`loom:deploy/compose.model-vision.yml:4`). The licence matters for any commercial use of the door.
- **COV-B-F9: the token floor is implemented twice.**
  - **Class and severity:** debt, low.
  - **Citation:** `raise_integer_token_floor` in `loom:crates/loom-backend-openai/src/lib.rs:151-170` and in `loom:crates/loom-client/src/tokens.rs:44-60`. The client's comment asserts that the two are identical (`loom:crates/loom-client/src/tokens.rs:28-29`), and no shared test pins them together.
  - **Consequence:** a fix to one floor silently diverges the client from the façade, which is the class of drift ADR-2084 set out to end.
- **COV-B-F10: stale default paths.**
  - **Class and severity:** drift, low.
  - **Citation:** `loom-scaffold` defaults its indexes to `~/githubs/loom/app/data/…` (`loom:crates/loom-scaffold/src/tuning.rs:69`, `:71`, used at `loom:crates/loom-scaffold/src/lib.rs:340-354`). `app/` now holds only `mirror.sh`, and the façade overrides the path to `/app/data/…` (`loom:crates/loom-facade/src/config.rs:160-161`). `loom:legacy/README.md:4` names `../docker-compose.yml`, which does not exist at the pin; the root holds no compose file.
  - **Consequence:** a non-façade caller of `loom-scaffold` that sets neither `ONTOLOGY_INDEX` nor a path loads nothing.
- **COV-B-F11: loom has no topic set; the adapter ring and model engine are undrawn.**
  - **Class and severity:** gap, medium.
  - **Citation:** there is no `docs/diagrams/loom/`. Loom appears through ES-01, ES-06, ES-12 and AB-24 only. None of them cites the graph store, embedder, backend seam, ledger internals, `loom-client` source or `model/`.
  - **Consequence:** F1 to F3 and F5 to F6 sat outside every diagram's citations, which is how the coverage script missed them. A short loom topic for the adapter ring and model engine, citing the lines above, would close it.

## Verification

Evidence class: **source tracing at the pinned revision**. Every loom citation was read with `git show ba21a689a57d:<path>`, `git ls-tree` or `git grep` at loom `ba21a689a57d`. Corpus citations were read in this worktree. Nothing was built, run or tested, and no runtime or deployment state was observed.

Read at the pin:

- the root `Cargo.toml`;
- the full `src/lib.rs` of `loom-graph-oxigraph`, `loom-backend-openai`, `loom-embed-xinference` and `loom-attest-proofgate`;
- `loom-client`'s `lib.rs`, `client.rs`, `request.rs` (excerpts), `tokens.rs` and `error.rs` (excerpts);
- `loom-scaffold`'s `lib.rs` (excerpts), `policy.rs`, `tuning.rs` and `match_.rs`;
- `loom-bench`'s `lib.rs` and `main.rs` (head and grep);
- all four scripts, `app/mirror.sh` (head and tail), `model/Dockerfile` and `model/serve-qwen38.sh`;
- `deploy/compose.model-vision.yml` and `deploy/Dockerfile.dockerignore`;
- the routing-eval, ingest, legacy and bench READMEs and notes;
- `dream.config.json`;
- the façade call sites: `lib.rs`, `state.rs`, `routes/mod.rs`, `error.rs`, `config.rs` and `mcp_host.rs`.

`tools/paper/*.py`, `bench/quality`, `bench/sweep` and the `uplift-results` contents were dispositioned by role and absence of importers, not read line by line.

Not checkable from source:

- whether Xinference ever returns a long non-ASCII error body (F2);
- the agentbox-side consumers of `loom-client`, which are outside this row's pins;
- whether oxigraph's `Store::query` (`loom:crates/loom-graph-oxigraph/src/lib.rs:259`) would itself refuse updates or `SERVICE`. That would make F1's regex defence in depth rather than the only control, but oxigraph's source is not pinned in this wave.
